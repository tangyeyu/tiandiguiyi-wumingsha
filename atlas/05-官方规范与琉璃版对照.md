# 05 · 官方规范 × 琉璃版 5.5 对照

> 官方仓库：**[libnoname/noname](https://github.com/libnoname/noname)**（GPL-3.0，约 4970 star）
> 本仓库开发目标：**琉璃版 5.5（电脑版）**，即官方的一个**旧架构 fork**
>
> **本文的用途**：官方有完整文档、且已全面转向 `async content`；
> 但琉璃版是旧引擎，**大部分官方新写法在琉璃版会直接失败**。
> 下表把「官方怎么说」与「琉璃版能不能用」逐条对齐，避免照抄官方文档把游戏写崩。

## 二、官方的「编写武将」硬性规范（CONTRIBUTING.md 原文要点）

> - 新增或重写技能的 `content` 时，**必须使用 `Async Content`**，显式声明 `event`、`trigger` 和 `player` 参数
> - **不要新增 `Step Content`**
> - 调用支持对象参数的 `Player` 事件方法时，**必须使用对象参数**，不要混用
> - 例外：`draw(2)` / `damage(2)` / `recover(1)` / `loseMaxHp(1)` / `gainMaxHp(1)` 等单数字调用可继续使用
> - JavaScript 用 **Tab 缩进**；新增公共方法写 JSDoc
> - PR 标题遵循 Conventional Commits，例：`feat(character): 添加武将张三及其技能`

**这三条里，只有第一条（async）与第三条（对象参数）在琉璃版不适用。** 其余（Tab、JSDoc、单一目的 PR）是通用工程规范。

## 四、三种 `content` 写法的官方定位

`docs/game-event/content.md` 给出的现状：

| 写法 | 官方状态 | 示例 |
|---|---|---|
| 单 async 函数 | **推荐**（目标格式） | `content: async (event, trigger, player) => { await player.draw(2); }` |
| 函数数组 | 待废弃（次优先） | `content: [fn1, fn2, fn3]` |
| step 语法 | 待废弃（**优先迁移**，官方约 3886 处） | `content: function(){ "step 0"; ... }` |

编译链：

```text
单 async 函数 → AsyncCompiler（纯适配层） ┐
旧 step 函数  → StepCompiler（解析）      ├→ ArrayCompiler（唯一执行引擎）
函数数组直接传 → 跳过预处理                ┘
```

`ArrayCompiler` 每步：

```text
beforeExecute → event.step++ → isPrevented（角色死亡/离场则 finish）
  → 执行 content[step](event, trigger, player, event._result)
  → await event.waitNext() → 合并子事件 result 到 event._result → afterExecute
```

## 五、★ 琉璃版兼容矩阵（实测）

**实测方法**：`atlas/tools/liuli-content-support.mjs` 忠实复刻琉璃版 `game.js:12070–12133` 的 `parsex` 三分支，
对每种写法真跑一遍编译判定。

| 官方写法 | 琉璃版 | 实测结果 |
|---|---|---|
| `content: async (e,t,p) => { ... }`（**含 await**） | ❌ **不可用** | `SyntaxError: await is only valid in async functions` |
| `content: async (e,t,p) => { ... }`（无 await） | ⚠️ 能编译但语义错 | 走 `Legacy()` 当同步函数编译，返回的 Promise 被丢弃 |
| `content: function(){ 'step 0'; ... }`（**step 顶格**） | ✅ 可用 | **两条分支下都可编译** —— 唯一安全写法 |
| `content: function(){ 'step 0'; if(x){ 'step 1'; } }`（**step 嵌套**） | ❌ **不可用** | `old` 分支硬报 SyntaxError；`Legacy()` 分支静默错位 |
| `content: function* (e, {player}) { yield ... }`（generator） | ❌ **不可用**（`old` 分支） | 仅 `else` 分支可用 —— **取决于 `finalParsex`** |
| `content: [fn1, fn2]` | ✅ 可用 | 走数组分支 |
| `await xxx.forResult()` | ❌ 不存在 | `game.js` 中 `forResult` 命中 **0** 次 |
| `cost: async function(){...}` | ❌ 不存在 | `cost:` 命中 **0** 次 |
| `event.waitNext()` / `event.insertAfter()` | ❌ / 部分 | `waitNext` 命中 0 次 |
| `player.gain({ cards, source, animate })` 对象参数 | ❌ 不支持 | 琉璃版全库统一用位置参数 `gain(cards,'gain2')` |
| 武将 **对象式**定义 `{sex,group,hp,skills}` | ❌ **会崩游戏** | 见下 |
| 武将 **数组式**定义 | ✅ 可用 | 注册链按位置下标取用 |

### 5.1 为什么 async 在琉璃版会抛错

琉璃版 `parsex` 只把 **`GeneratorFunction`** 当特殊分支（`game.js:374`）：

```js
const GeneratorFunction = (function*(){}).constructor;
generatorFunc: item => item instanceof GeneratorFunction,
```

`async function` 的构造器是 `AsyncFunction`，**不是** `GeneratorFunction` → 掉进 `Legacy()`。
而 `Legacy()` 把函数体源码切出来，用 **非 async** 的 `new Function()` 重新编译（`game.js:12131`）——
函数体里的 `await` 立刻成为语法错误。且 `Legacy()` **没有 try/catch**，异常直接向上抛。

> 琉璃版 `game.js` 中 `AsyncFunction` 出现 **0** 次 —— 全引擎没有任何 async 支持。

### 5.2 为什么对象式武将会崩游戏

官方写法：

```js
myhero: { sex: "male", group: "wei", hp: 4, skills: ["myskill"] }
```

琉璃版 `game.import('character')` 注册链按**位置下标**取用（`game.js:15146–15157`）：

```js
if(!character[i][j][k][4]){ character[i][j][k][4]=[]; }        // 第 5 位 = 包归属
for(var l=0;l<character[i][j][k][3].length;l++){ ... }         // 第 4 位 = 技能数组
```

对象上没有 `[3]` → `character[i][j][k][3].length` 抛 **TypeError** → **启动即崩**。

> 注意区分：`game.addCharacter(name, {...})` **接受对象式**（`game.js:40363` 手工转数组），
> 那是"扩展内逐个加武将"的辅助 API；而武将包走 `game.import('character')` 注册链，**只吃数组式**。
> `game.addCharacterPack(pack)` 同样用 `pack[i][j][3]` / `[4]`（`game.js:40388–40408`）—— 也是数组式。

## 六、琉璃版实际可用的两套写法

### 6.1 step 写法（旧制，但最普及）

```js
myskill: {
    audio: 2,
    trigger: { player: 'phaseZhunbeiBegin' },
    forced: true,
    content: function () {
        'step 0'
        player.draw(2);
        'step 1'
        if (player.countCards('h') > 5) { player.chooseToDiscard(2, true); }
    },
}
```

**必须遵守 [`01-引擎契约.md`](01-引擎契约.md) 推论 7a / 7b：步骤标记只能顶格写，不能嵌套、不能重复。**

### 6.2 generator 写法 —— ⚠️ **不推荐**（取决于 `finalParsex`，实测踩雷）

```js
// 只在 finalParsex != 'old' 时可用；为 'old' 时会抛 SyntaxError
content: function* (event, { player, trigger }) {
    const result = yield player.draw(2);
}
```

**为什么之前误判为可用**：琉璃版 `parsex` 有**两条分支**（`game.js:12070-12091`），由
`localStorage.getItem('finalParsex')` 决定，而只有 `else` 分支带 `gnc.isGeneratorFunc` 判断：

```js
parsex:function(item){
    var psx=localStorage.getItem('finalParsex');
    if(psx&&psx=='old'){                     // ← 分支 A
        var str=item.toString();
        str=str.slice(str.indexOf('{')+1);   // ← 无 generator 判断
        ...
        return (new Function(..., str));     // ← 无 try/catch
    } else {                                 // ← 分支 B
        function Legacy(func){...}
        switch(typeof item){ case "function":
            if (gnc.isGeneratorFunc(item)) { ... }   // ← 只有这里有
            return Legacy(item);
        }
    }
}
```

在分支 A 里，`function* (event, { player })` 的**第一个 `{` 落在解构参数中**，
`slice` 从那里切开得到 ` player }) {...` → `new Function` 抛 `SyntaxError: Unexpected token ')'`。

**⇒ 结论：不要用 generator。** 只有「普通函数 + `'step N'` 顶格」在两条分支下都安全。
（若确要用 generator，需先确认目标机器的 `finalParsex` 不为 `'old'` —— 该值可在
Console 里用 `localStorage.getItem('finalParsex')` 查看。）

> **教训**：只建模 `parsex` 的一条分支会得出完全相反的结论。
> 校验必须用 `atlas/tools/verify-extension.mjs`（对每个 content 分别在两条分支下编译）。

## 七、琉璃版里已经踩到这颗雷的地方

全库检索 `async content` / `forResult` 的实际使用：

| 位置 | 内容 | 状态 |
|---|---|---|
| `character/tw.js:15094` | `async content(...)`，含 `await ... .forResult()` | **不可达**（见下） |
| `character/tw.js:15133` | `async content(...)`，含 `await player.draw(sum)` | **不可达** |
| `extension/皮肤切换/extension.js:187` | `async content(event, player)` | 需单独确认可达性 |
| `character/collab.js:3206/3240`、`sp2.js:713/813` | `//content:function*(event,map)` | 已被注释 |

`tw.js` 的两处属于孤儿技能 —— 已用索引核实：

```text
twxianyuan（仙援）在 tw.js:15015 定义，group: ["twxianyuan_effect", "twxianyuan_remove"]，
但全库 113 个 tw 武将中没有任何一个引用它 → 技能不可达，所以未崩。
```

**风险提示**：这是**潜在陷阱**而非现存 bug。
一旦有人把 `twxianyuan` 挂到某武将身上（或把那两段 `async content` 当作模板照抄），
由于 `twxianyuan_remove` 是 `forced: true` + `trigger:{player:'phaseBegin'}`，
**该武将每回合开始都会抛 `SyntaxError`**。

## 八、行动准则（写琉璃版技能时）

- [ ] **不要用 `async content`** —— 含 `await` 必崩；无 `await` 能编译但语义错
- [ ] **不要用 `forResult()` / `cost` / 对象参数** —— 琉璃版不存在这些 API
- [ ] **武将定义用数组式** `['male','wei',4,['skillA'],['wei']]` —— 对象式会崩启动
- [ ] 想要 async 的可读性 → **用 `function*` generator**
- [ ] 用 step 时，**步骤标记顶格、不嵌套、不重复**（对照 `atlas/tools/parsex-probe.mjs` 自检）
- [ ] 从官方文档抄字段名时，先在本表确认该字段琉璃版是否支持
- [ ] 官方 `lib-skill-format.md` 里的**字段语义**（trigger/filter/check/enable/viewAs/mod/group/subSkill/ai）与琉璃版基本一致，可放心参考

> 一句话：**官方的字段表能用，官方的写法不能用。**
> 琉璃版是 step/generator 时代，官方是 async 时代；照抄官网代码是本仓库最容易被忽略的崩游戏原因。
