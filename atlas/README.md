## 方法论

三条原则，直接决定了本 atlas 的可信度：

### 1. 词法扫描，绝不执行目标代码

`character/*.js` 在加载期会读 `window` / `lib` / `game` 并含大量第三方式全局，`eval` 化既不可靠也会污染环境。
因此工具链全部基于**自写词法切分器 + 括号配对**：跳字符串、跳注释、识别正则字面量，只在记号流上做结构提取。

代价是要自己处理正则字面量歧义（`/` 是除法还是正则），收益是**零副作用、可对任意包文件运行**。

### 2. 样例是数据驱动选出来的，不是凭感觉挑的

`classify-skills.mjs` 先用 37 个特征标记给全部 5227 个技能打标，再按
**行数升序 + 技能名规范 + 同包最多 2 个**排序，产出候选表。
`02-范式库.md` 里的每个样例都取自这张表，因此都是「该范式下最纯粹的最小实现」。

### 3. 结论必须能复现

文档里每个技能都标注 `包:技能 @ 文件:行`。任何人一条命令即可取出同一段源码：

```bash
node atlas/tools/extract-skill.mjs <character目录> atlas/index jiange:lingfeng
```

## 工具

四个脚本，纯 Node（无依赖），用于生成索引、抽样与体检。

```bash
# ① 结构索引：包名 / 武将 / 技能 / 行号区间
node atlas/tools/index-packs.mjs <character目录> atlas/index

# ② 范式普查 + 样例推荐
node atlas/tools/classify-skills.mjs <character目录> atlas/index

# ③ 命名空间体检（★ 必须带 --app，否则"悬空引用"会有假阳性）
node atlas/tools/check-collisions.mjs atlas/index atlas/index --app <游戏app根目录>

# ④ 按"包:技能"精确抽取源码
node atlas/tools/extract-skill.mjs <character目录> atlas/index <包>:<技能> [...]

# ⑤ 单技能编译探针：打印 parsex 的替换轨迹、残留 step、结束步 K
node atlas/tools/parsex-probe.mjs <扩展js> <技能名> [起始行 结束行]

# ⑥ 全库编译体检：真的跑一遍 parsex，统计有多少技能编译后有残留 step
node atlas/tools/parsex-audit.mjs <character目录> atlas/index [扩展目录...]
```

`<character目录>` 指游戏的 `resources/app/character/`。
`<游戏app根目录>` 指 `resources/app/`（用于补充扫描引擎内建 / 模式 / 扩展中定义的技能）。

### 工具做了什么

| 工具 | 关键能力 |
|---|---|
| `index-packs.mjs` | 定位 `game.import('character', ...)` 回调体 → 找 `return {}` 包对象 → 提取 `character` / `skill` 的顶层键与行号区间；武将数组按**顶层逗号切元素**后取第 4 项解析技能引用 |
| `classify-skills.mjs` | 按技能自身行区间做特征匹配（不跨技能误判）；统计范式覆盖率；按体量+跨包去重推荐样例 |
| `check-collisions.mjs` | 三类体检：技能名跨包重复 / 武将 id 重复 / 悬空技能引用；带 `--app` 时补充扫描 `character/` 之外的技能定义来源 |
| `extract-skill.mjs` | 支持**跨包回退**：本包找不到时全库搜索并报出真实定义位置（技能是全局命名空间的） |
| `parsex-probe.mjs` | 照抄 `parsex` 算法（`game.js:12094–12133`）对单个 `content` 做编译，打印替换轨迹与被静默跳过的位置 |
| `parsex-audit.mjs` | 对全库每个技能的 `content` 跑一遍 `parsex`，统计编译后有残留 `'step N'`（= 状态机错位）的技能 |

## 数据快照

以本 atlas 生成时的扫描为准：

| 指标 | 值 |
|---|---|
| 包文件 | 34（`rank.js` 是分级表，非武将包，已排除） |
| 总行数 | 270,265 |
| 武将 | 1,885 |
| 技能定义 | 5,227 |
| 技能行数中位数 | 35 |
| 技能行数最大值 | 1,095 |
| ≤10 行的技能 | 约 1/4 |
| 命名空间冲突 | 9 处技能名重复 |
| 真悬空引用 | 1 处 |

**这个分布本身就是一条结论**：绝大多数技能是短小的。
**先用最小范式写对，再叠加复杂度** —— 这是本 atlas 全部取样的依据。

## 适用范围与局限

**适用**：琉璃版 5.5（电脑版）的无名杀引擎，即 `resources/app/` 下的这份实现。
不同版本的 `game.js` 行号会漂移，但**机制契约是稳定的**（`step` 编译、全局技能表、事件段模型）。

**已知局限**

- 本 atlas 只**静态**分析。技能的运行期行为（尤其 AI 的实际表现）未做动态验证。
- `check-collisions.mjs` 的 `--app` 补充扫描是**文本级**的，可能把"恰好同名"的非技能对象键误认为技能定义。判定「真悬空」前建议再人工确认一次。
- 覆盖冲突的**胜者**（谁覆盖谁）依赖 `lib.config.all.characters` 的运行期顺序，**静态无法确定** —— 详见 [`03-命名空间与冲突.md`](03-命名空间与冲突.md) §3.2。
- 范式库当前覆盖 11 个范式；`index/samples.md` 里还有约 26 个范式已普查但未逐一深挖。

**关于引用**：本目录是**分析性文档**，包含为说明机制而引用的短代码片段（每个样例 ≤ 50 行）。
不含任何武将包源码的全量镜像，也不替代原包。

> 引擎机制结论均标注 `game.js` 行号，可自行复核。
