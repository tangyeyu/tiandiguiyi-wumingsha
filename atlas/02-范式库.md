## A1 · 零逻辑声明式技能

**一句话**：什么逻辑都不写，只声明「由哪些技能组成、用哪个语音」。

**样例**：`refresh:rexiansi` — `refresh.js:2511-2516`（6 行），武将 `re_liufeng`

```js
rexiansi:{
    inherit:'xiansi',
    audio:'xiansi',
    audioname:['re_liufeng'],
    group:['rexiansi2','xiansix'],
},
```

**逐字段**

| 字段 | 作用 |
|---|---|
| `inherit:'xiansi'` | 复用 `xiansi` 的全部字段。**本对象里显式写的会覆盖它** |
| `audio:'xiansi'` | 语音文件名前缀指向 `xiansi.*`（复用原版语音素材） |
| `audioname:['re_liufeng']` | 该武将专属语音变体 |
| `group:['rexiansi2','xiansix']` | 把这两个技能的**触发器挂到本技能名下**（`game.js:27808 addSkillTrigger`） |

**要点**：`rexiansi2` / `xiansix` **不在**武将的技能数组里。它们靠 `group` 挂入，所以 `extract-skill` 会显示「无直接引用」。这是**正常**的，`standard:wushuang` 同理。

**陷阱**
- 把 `group` 成员**也**写进武将数组 → 技能框重复显示，且 `removeSkill` 时只摘掉一半。
- 改 `inherit` 的源技能 → 会**连锁**影响所有继承它的技能。修改 `xiansi` 前先全库搜 `inherit:'xiansi'`。

## A2 · 纯声明式技能组（引擎内最经典的一个）

**一句话**：一个「技能」其实是**若干子技能触发器的聚合入口**。

**样例**：`standard:lvbu` 的技能数组只有 `['wushuang']`：

```js
// standard.js:2186-2194
wushuang:{
    shaRelated:true,
    audio:2,
    audioname:['re_lvbu','shen_lvbu','lvlingqi'],
    forced:true,
    locked:true,
    group:['wushuang1','wushuang2'],
    preHidden:['wushuang1','wushuang2'],
},
```

**注意：它没有 `content`。** 全部行为在两个成员里：

```js
// standard.js:2195-2222 —— 【杀】需要两张闪
wushuang1:{
    audio:'wushuang',
    audioname:['re_lvbu','shen_lvbu','lvlingqi'],
    trigger:{player:'useCardToPlayered'},
    forced:true,
    filter:function(event,player){
        return event.card.name=='sha'&&!event.getParent().directHit.contains(event.target);
    },
    logTarget:'target',
    content:function(){
        var id=trigger.target.playerid;
        var map=trigger.getParent().customArgs;
        if(!map[id]) map[id]={};
        if(typeof map[id].shanRequired=='number'){ map[id].shanRequired++; }
        else{ map[id].shanRequired=2; }
    },
    ai:{
        directHit_ai:true,
        skillTagFilter:function(player,tag,arg){
            if(arg.card.name!='sha'||arg.target.countCards('h','shan')>1) return false;
        },
    },
},
```

```js
// standard.js:2223-2250 —— 【决斗】对手需连续打出两张杀
wushuang2:{
    audio:'wushuang',
    audioname:['re_lvbu','shen_lvbu','lvlingqi'],
    trigger:{player:'useCardToPlayered',target:'useCardToTargeted'},
    forced:true,
    logTarget:function(trigger,player){ return player==trigger.player?trigger.target:trigger.player },
    filter:function(event,player){ return event.card.name=='juedou' },
    content:function(){
        var id=(player==trigger.player?trigger.target:trigger.player)['playerid'];
        var idt=trigger.target.playerid;
        var map=trigger.getParent().customArgs;
        if(!map[idt]) map[idt]={};
        if(!map[idt].shaReq) map[idt].shaReq={};
        if(!map[idt].shaReq[id]) map[idt].shaReq[id]=1;
        map[idt].shaReq[id]++;
    },
    ai:{ directHit_ai:true, skillTagFilter:function(player,tag,arg){ /* ... */ } },
},
```

**这一组为什么值得逐行读**

1. **`group` 而不是数组**：`lvbu` 只列 `wushuang`。三个技能实体，一个技能框。
2. **`trigger.getParent().customArgs`** 是**改结算参数**的标准入口 —— 你不是在"造成效果"，而是在**改写正在结算的那张牌的参数表**。这是无名杀最核心的干预手段。
3. **`filter` 里排除 `directHit`**：`!event.getParent().directHit.contains(event.target)`。没有这一句，无双对「不可被响应」的杀也生效 → 语义错误。
4. **`trigger` 声明了两个视角**：`{player:..., target:...}` —— 无论自己是使用者还是目标，都会触发。`content` 里再用 `player==trigger.player` 判断站在哪一侧。
5. **`ai.skillTagFilter`** 是**给 AI 的"此技能此刻是否算数"标签**，与 `filter` **不是一回事**。`filter` 决定能不能发动，`skillTagFilter` 只影响 AI 对【杀】的价值评估（此处：对手只有 1 张闪时，无双不改变结果，故不提高评估）。

**陷阱**
- 直接改 `event.card` 的属性去实现"需要两张闪" → 无效。牌的使用规则在 `customArgs`，不在 card 上。
- 漏掉 `directHit` 判断 → 与「不可响应」类效果冲突。

## A3 · 继承 + 只覆盖 `content`

**一句话**：注册层照抄原型，只换逻辑本体。

**样例**：`offline:yjzhenlve` — `offline.js:5910-5916`（7 行），武将 `yj_jiaxu`

```js
yjzhenlve:{
    audio:'zhenlve',
    inherit:'zhenlue',
    content:function(){
        trigger.directHit.addArray(game.players);
    }
},
```

**要点**
- 触发时机、`forced`、`filter`、`ai` **全部**来自 `zhenlue`，此处只换 `content`。
- `trigger.directHit.addArray(game.players)`：把**触发源事件的** `directHit` 集合填满全场 → 该牌不可被任何人响应。
- `directHit` 是**事件字段**（`trigger` = 触发源事件），不是 player 的方法。

**陷阱**
- 覆盖 `content` 时**必须确认源技能 `content` 里没有初始化副作用**（如 `event.cards=[]`、往 `player.storage` 写值）。漏掉会满屏报错。
  **正确做法**：先 `extract-skill` 把源技能完整读出来，列出它的初始化语句，逐条在新 `content` 里补齐。

## A4 · 限定技最小骨架

**样例**：`refresh:jiezhong` — `refresh.js:5685-5698`（14 行），武将 `re_guanping`

```js
jiezhong:{
    audio:2,
    trigger:{player:'phaseUseBegin'},
    limited:true,
    skillAnimation:true,
    animationColor:'orange',
    filter:function(event,player){
        return player.countCards('h')<player.maxHp;
    },
    content:function(){
        player.awakenSkill('jiezhong');
        player.draw(Math.min(5,player.maxHp-player.countCards('h')));
    },
},
```

**逐字段**
- `limited:true` → 引擎自动补 `intro.content='limited'`、`skillAnimation=true`、`init: player.storage[skill]=false`（`game.js:44148-44151`）
- `skillAnimation` + `animationColor:'orange'` → 发动时播橙色限定技动画
- `filter` → 硬门槛：手牌数 < 体力上限才可发动
- `awakenSkill('jiezhong')` → **必须在 content 第一行**。它做四件事（`game.js:28286`）：
  1. `unmarkSkill(skill)` 取消标记显示
  2. `disableSkill(skill+'_awake', skill)` 通过影子技能禁用本体
  3. `awakenedSkills.add(skill)` 记入已觉醒集合
  4. `if(this.storage[skill]===false) this.storage[skill]=true` ← **只在初值为 `false` 时才置 true**

**第 4 条是理解全局的关键**：`awakenSkill` 依赖 `storage[skill]` 已被初始化为 `false`。
所以**自建限定技时，要么用 `limited:true`（引擎自动 init），要么自己写 `init`**。
否则 `storage[skill]` 是 `undefined`，第 4 条不执行 —— 依赖 `player.storage[skill]` 做判断的后续逻辑会全部失效。
（这正是 `extension/十周年UI/markskill.js:7801` 给 `resghuishi` 补 `init` 的原因。）

**陷阱**
- 忘了 `awakenSkill()` → 限定技可以反复发动。
- 自己写 `limited:true` 但**又**手写 `init` 覆盖 → 与引擎默认值打架，注意别把初值写成 `true`。

## A5 · 觉醒技最小骨架

**样例**：`sb:sbdujiang` — `sb.js:7906-7922`（17 行），武将 `sb_lvmeng`

```js
sbdujiang:{
    audio:2,
    trigger:{player:'phaseZhunbeiBegin'},
    derivation:'sbduojing',
    juexingji:true,
    forced:true,
    skillAnimation:true,
    animationColor:'wood',
    filter:function(event,player){
        return player.hujia>=3;
    },
    content:function(){
        player.awakenSkill('sbdujiang');
        player.addSkillLog('sbduojing');
        player.storage.sbkeji=true;
    }
},
```

**逐字段**
- `juexingji:true` → **标签**。作用有两个：① 检索型技能（如「辉逝」）能筛出它；② 引擎在结算觉醒时排除已觉醒的。
- `derivation:'sbduojing'` → 声明衍生技。**它不会自动授予**，只是让展示层与 AI 知道「这个技能会带出 `sbduojing`」。
- `forced:true` → 条件满足强制觉醒
- `addSkillLog('sbduojing')` → 授予衍生技**并记入技能获得日志**（用 `addSkill` 则无日志）
- `player.storage.sbkeji=true` → 用 storage 存一个**标志位**给 `sbduojing` 读

**`juexingji` vs `awakenSkill()` —— 这是本 atlas 里最容易混的一对**

| | `juexingji:true` | `awakenSkill()` |
|---|---|---|
| 性质 | 声明/标签 | 执行动作 |
| 作用 | 让别的技能**能找到**它；标记它是觉醒技 | 退役：禁用本体 + 写入 `awakenedSkills` |
| 漏写的后果 | 检索型技能找不到它（如辉逝无法解锁） | 觉醒技可反复发动 |
| 写在哪 | 技能对象字段 | `content` 首行 |

**两个都写才算正确。**

## A6 · 前置取消：替换掉一个阶段动作

**样例**：`jiange:lingfeng` — `jiange.js:248-283`（36 行），武将 `jg_liubei`

```js
lingfeng:{
    trigger:{player:'phaseDrawBefore'},
    check:function(event,player){
        for(var i=0;i<game.players.length;i++){
            if(player!=game.players[i]){
                if(get.attitude(player,game.players[i])<0) return true;
            }
        }
        return false;
    },
    content:function(){
        "step 0"
        trigger.cancel();
        event.cards=get.cards(2);
        player.showCards(event.cards);
        "step 1"
        if(get.color(event.cards[0])!=get.color(event.cards[1])){
            player.chooseTarget('是否弃置一名角色一张牌？',function(card,player,target){
                return player!=target&&target.countCards('he')>0;
            }).ai=function(target){
                return -get.attitude(player,target);
            }
        }
        "step 2"
        if(result.bool&&result.targets&&result.targets.length){
            player.discardPlayerCard(result.targets[0],'he',true);
        }
        "step 3"
        player.gain(event.cards);
        player.$draw(event.cards);
        game.delay();
    },
    ai:{ threaten:1.1 },
},
```

**要点**

1. **挂 `phaseDrawBefore` 而非 `phaseDrawEnd`**：只有 `Before`/`Begin` 段能 `cancel()`（见 [`01-引擎契约.md`](01-引擎契约.md) 推论 11）。
2. **`trigger.cancel()`** = 取消「摸牌阶段」这个事件本身 → 玩家不再摸牌，改由本技能给牌。
3. **`event.cards=get.cards(2)`**：从牌堆顶取 2 张，**存进本事件字段**。因为 `cards` 这个注入变量每步重读 `event.cards`，所以下一步可以直接用。
   **这是「跨步保存牌」的标准写法**，比存到局部变量更稳（局部变量在 step 间不共享）。
4. **`check` 而非 `filter`**：这是**AI 决策**（有敌人就发动），人类玩家仍会被询问是否发动。**正确用法。**
5. **`step 1` 里可能不创建选择事件**：如果两牌同色，跳过 `chooseTarget` → 引擎直接进 `step 2`，此时 `result` 是 `undefined`。所以 `step 2` 写的是 `result.bool && result.targets && result.targets.length` —— **三重判空，正是为这条路径准备的**。
   **这是本范例最值得学的一行。**
6. `.ai=function(target){...}` 直接给 `chooseTarget` 返回的事件赋 `ai`，等价于 `.set('ai', fn)`。

**陷阱**
- 在 `phaseDraw`（无 Before/After 后缀）上挂 → 时机错，取消不了或已摸完。
- `step 2` 直接写 `result.bool` → 同色路径抛错。

## A7 · `filter` 硬门槛 vs `check` AI 决策（同名的两个技能，正好对照）

包 `swd` 里有一个**同名但完全不同**的技能：

**样例**：`swd:lingfeng` — `swd.js:1473-1504`（32 行），武将 `swd_huiyan`

```js
lingfeng:{
    trigger:{player:'phaseEnd'},
    frequent:true,
    filter:function(event,player){
        return player.countUsed()>=Math.min(3,player.hp);
    },
    content:function(){
        'step 0'
        player.chooseTarget('凌锋',function(card,player,target){
            return player!=target&&get.distance(player,target,'attack')<=1;
        }).set('prompt2','造成一点伤害，或取消并获得一点护甲').ai=function(target){
            if(player.hp==1) return 0;
            if(player.hp==2&&target.hp>=3) return 0;
            return get.damageEffect(target,player,player);
        }
        'step 1'
        if(result.bool){
            player.line(result.targets[0]);
            result.targets[0].damage();
        }
        else{
            player.changeHujia();
        }
    },
    ai:{ order:-10, result:{ target:2 }, threaten:1.5 },
},
```

**对照表**

| | `jiange:lingfeng` (A6) | `swd:lingfeng` (A7) |
|---|---|---|
| 门槛字段 | `check` | `filter` |
| 含义 | **AI 决策**：有敌人时 AI 主动发动 | **硬门槛**：使用牌数 ≥ min(3, 体力) 才可发动 |
| 人类玩家 | 仍会被询问 | 条件不满足时**技能不点亮** |
| 是否合理 | ✅ 条件主观，应交给人 | ✅ 条件客观，作为规则门槛 |

**判据（可直接套用）**
> 门槛是**客观数值/状态**（体力、牌数、距离）→ 用 `filter`
> 门槛是**主观取舍**（要不要冒这个险）→ 用 `check`，把决定权留给玩家

**陷阱**
- 把主观判断写进 `filter` → 人类玩家被 AI 逻辑绑架，技能"该亮的时候不亮"。
- `prompt2` 是**副提示**（在标题下的小字），不是换行符拼接。用 `\\n` 拼字符串是错的。

> ⚠️ 这两个 `lingfeng` **同时存在于本仓库**，构成 9 处技能名冲突之一。
> 谁生效取决于包加载序 —— 详见 [`03-命名空间与冲突.md`](03-命名空间与冲突.md)。

## A8 · 转化技 `backup`：不消耗牌 + 预结算钩

**一句话**：`chooseButton` 选一个牌名 → `backup` 生成一个「不需要实体牌、视为使用该牌」的临时技能。

**样例**：`sp:aocai_backup` — `sp.js:21920-21933`（14 行）

```js
aocai_backup:{
    sourceSkill:'aocai',
    precontent:function(){
        delete event.result.skill;
        var name=event.result.card.name,cards=event.result.card.cards.slice(0);
        event.result.cards=cards;
        var rcard=cards[0],card;
        if(rcard.name==name) card=get.autoViewAs(rcard);
        else card=get.autoViewAs({name,isCard:true});
        event.result.card=card;
    },
    filterCard:function(){return false},
    selectCard:-1,
},
```

**逐行**

| 行 | 作用 |
|---|---|
| `sourceSkill:'aocai'` | 标注归属的主技能。用于：防止递归调用自身、日志归类、AI 认知 |
| `precontent` | **独立的事件状态机**，在使用结算**之前**执行（`game.js:16421` / `16602` 创建 `next.setContent(info.precontent)`）。它可以有自己的 `'step N'` |
| `delete event.result.skill` | **抹掉转化来源标记**。不删的话，这张牌会被识别为"由技能转化而来"，导致 `<name>_info` 类判定、`get.is.converted` 判断全部走错分支 |
| `event.result.cards = cards` | 把**实体牌**挂回去。因为是 `selectCard:-1` 虚拟使用，默认没有实体牌 → 必须手动补，否则「弃置/展示此牌」类后续效果拿到空集 |
| `get.autoViewAs(...)` | 构造牌的"视为"视图：若顶牌本身就同名则直接用，否则构造虚拟牌 |
| `filterCard:()=>false` | 任何牌都不可选 |
| `selectCard:-1` | 且不需要选牌 → **零消耗发动** |

**为什么 `filterCard` 和 `selectCard` 要成对**
两者缺一：只写 `filterCard:()=>false` → 引擎仍要求选牌，而没有任何牌可选 → 卡死在选择界面；
只写 `selectCard:-1` → 仍会列出可选的牌。**必须成对。**

**陷阱**
- 漏 `delete event.result.skill` → 最隐蔽的一类 bug：技能能发动、牌能用，但**下游所有"是否为转化牌"的判定全部错误**。
- 漏补 `event.result.cards` → 「获得此牌/弃置此牌」类效果拿到空数组。
- `precontent` 里**不要**做需要玩家输入的操作（它在结算链上，会打乱事件嵌套序）。

## A9 · `mod` 钩子 + 空壳子技能

**一句话**：不是"发生什么时做什么"，而是**改写引擎的查询结果**。

**样例**：`ddd:dddfusi` — `ddd.js:1692-1712`（21 行），武将 `ddd_xianglang`

```js
dddfusi:{
    mod:{
        ignoredHandcard:function (card,player){
            if(get.is.shownCard(card)) return true;
        },
        cardDiscardable:function (card,player,name){
            if(name=='phaseDiscard'&&get.is.shownCard(card)) return false;
        },
    },
    global:"dddfusi_global",
    subSkill:{
        refused:{ charlotte:true, sub:true },
        allowed:{ charlotte:true, sub:true },
    },
},
```

**要点**

1. **`mod` 是查询钩子表**，不是事件。引擎在需要判断时调 `game.checkMod(...)`，内部按名字取 `info.mod[name]` 逐个执行（`game.js:44285`、`44298`）。
   → **`mod` 与 `trigger` 是两条完全不同的路。** 想让"某种牌不可被弃置"，用 `mod.cardDiscardable`；用 `trigger` 做不到，因为**根本没有事件发生**。
2. `ignoredHandcard` → 明牌不计入手牌数（查询期干预）
3. `cardDiscardable` → 弃牌阶段不可弃置明牌
4. `global:"dddfusi_global"` → **给全场玩家挂载** `dddfusi_global` 技能
5. `subSkill.refused` / `subSkill.allowed` → 只写了 `charlotte:true, sub:true`，**没有任何逻辑**。这是**空壳子技能**：注册出 `dddfusi_refused` / `dddfusi_allowed` 两个名字，纯粹**当状态位用**（由别处 `addSkill` / `removeSkill` 来开关）。
   `charlotte:true` 让它们**不出现在技能表**；`sub:true` 标记为子技能。

**`mod` 常用钩子**

| 钩子 | 干涉的查询 |
|---|---|
| `ignoredHandcard` | 手牌是否被计入（明牌/暗牌） |
| `cardDiscardable` | 某张牌当前能否被弃置 |
| `cardUsable` / `cardEnabled` | 某种牌能否使用 / 能否被指定 |
| `targetEnabled` | 能否成为某牌的目标 |
| `cardnumber` / `cardsuit` / `cardname` | 牌的点数 / 花色 / 名称 |
| `globalTo` | 牌的使用目标范围 |

**陷阱**
- 用 `trigger` 实现本该用 `mod` 的效果 → 事件根本不产生，技能永不触发。
- `mod` 函数**必须是纯查询**：不能有副作用（不能 `draw`、不能改 storage）。它会被高频调用。
- 空壳子技能忘了 `charlotte:true` → 出现在技能表里，玩家看到一个没有描述的空技能。

## A10 · 多步状态机 + storage 传牌

**样例**：`xianjian:zhimeng` — `xianjian.js:3865-3911`（47 行），武将 `pal_liumengli`

```js
zhimeng:{
    trigger:{player:'phaseEnd'},
    direct:true,
    locked:true,
    unique:true,
    gainable:true,
    // alter:true,
    group:'zhimeng3',
    content:function(){
        "step 0"
        player.chooseTarget(get.prompt('zhimeng'),function(card,player,target){
            return player!=target;
        }).ai=function(target){
            var num=get.attitude(player,target);
            if(num>0){
                if(player==target){ num++; }
                if(target.hp==1){ num+=3; }
                if(target.hp==2){ num+=1; }
            }
            return num;
        }
        "step 1"
        if(result.bool){
            var target=result.targets[0];
            if(get.is.altered('zhimeng')){
                target.draw();
            }
            else{
                var card=get.cards()[0];
                target.$draw(card);
                target.storage.zhimeng2=card;
                game.addVideo('storage',target,['zhimeng2',get.cardInfo(card),'card']);
                target.addSkill('zhimeng2');
            }
            player.logSkill('zhimeng',target);
        }
    },
    ai:{ expose:0.2 },
},
```

**要点**

1. **`direct:true` + `locked:true`**：不弹技能名、不播动画 —— 因为这是**回合结束自动结算**的技能，弹窗会打断节奏。
2. **`unique` / `gainable`**：参与「获得技能」体系，可被夺取/复制。
3. **`group:'zhimeng3'`**：单个字符串形式（对比 A1 的数组形式，两者等价）。`game.js:27808` 对 string 和 array 分别处理。
4. **`get.prompt('zhimeng')`** 而非手写 `'智盟'`：自动取 `translate` 里的名字，改文案时不用改代码。**推荐做法。**
5. **`get.is.altered('zhimeng')`**：读取「技能是否被改版」。配合上面注释掉的 `// alter:true` —— 这是无名杀 SD（界限突破）体系的开关。**注意这行是死代码路径**（`alter` 被注释，`get.is.altered` 恒为 false）。
6. **`target.storage.zhimeng2=card` + `target.addSkill('zhimeng2')`**：把一个**牌对象**存进 storage，并授予一个读它的子技能。
   `storage` 可以存任意对象，**不仅限于数字**（对比 `addMark` 只能存数字/数组）。
7. **`game.addVideo('storage',target,['zhimeng2',get.cardInfo(card),'card'])`**：把 storage 变更登记进录像。**联机/录像回放必备**，漏写会导致回放时状态不一致。

**`storage` vs 标记（`addMark`）的选择**

| | `addMark(name, n)` | `storage.name = x` |
|---|---|---|
| 存什么 | 数字（或数组，`countMark` 返回长度） | **任意值**（牌对象、玩家引用、字符串） |
| 显示 | 自动显示在头像旁 | 需配 `markSkill()` / `intro` |
| 日志 | 自动记「获得了N个【X】」 | 无，需手写 `game.log` |
| 录像 | 自动同步（`syncStorage`） | **需手写 `game.addVideo('storage',...)`** |

**陷阱**
- `storage` 写入后忘了 `addVideo` → 单机正常、**联机/录像出错**。
- 用 `addMark` 存非数字 → `countMark` 返回 0，`hasMark` 恒 false。
- 用 `get.translation` 手写提示文案 → 改文案要改代码。

## A11 · 反例：一个"半成品"技能

**样例**：`extra:zhimeng` — `extra.js:2818-2897`（80 行），武将 `shen_lusu`

> 这个技能**能跑**，但内部同时存在**三代写法**，是极好的「不要这样写」教材。

```js
zhimeng:{
    audio:2,
    trigger:{player:'phaseAfter'},
    filter(event,player){
        return game.hasPlayer(current=>{
            return current.countCards('h')+player.countCards('h')>0&&player!=current;
        })
    },
    direct:true,
    content(event,trigger,player){
        'step 0'
        /*const {result:{bool,targets}}=await */

            return target.countCards('h')+player.countCards('h')>0&&player!=target;

            const pvalue=-player.getCards('h').map(card=>get.value(card,player)).reduce((p,c)=>p+c,0);

            return (pvalue+tvalue)/2;
        });
        /*'step 1'
        ... 整段新版 async 写法，共 40 行，被 /* *\/ 注释掉 ...
        'step 2'*/
        'step 1'
        if(!result.bool) event.finish();

        event.card1=event.card.randomGets(event.num1);

        event.tar.gain(event.card2);

```

**问题清单**

| # | 问题 | 后果 / 原因 |
|---|---|---|
| 1 | **两套 `'step 1'` / `'step 2'`** —— 旧的被 `/* */` 注释掉，新的紧接其后 | 危险但**当时能跑**：`parsex` 的注释剥离（`game.js:12097`）会先删掉注释，`'step N'` 才被替换。一旦有人误删注释符，**立刻变成重复 case 标签 → 语法错误** |
| 2 | `content(event,trigger,player)` 新式签名 | **签名被 `parsex` 丢弃**（`game.js:12099` 切掉第一个 `{` 之前），这些参数名**完全不生效**，纯误导 |
| 3 | 注释里那句 `const {result:{bool,targets}}=await` | 若取消注释会**直接炸**：`parsex` 按第一个 `{` 切源码，`{result:{...}}` 会让切点落在解构上 |
| 4 | `'step 0'` 之后紧跟 `/* ... */` 再 `'step 1'` | 中间空转一步，`case 0:` 里只有 `chooseTarget`，可读性差 |
| 5 | `event.tar` 字段名 | 与引擎约定名 `event.target` 不一致。**下一步读 `target` 会拿到 `undefined`**，所以这里只能继续用 `event.tar` —— 全篇自造字段 |
| 6 | `game.hasPlayer(current=>{...})` 与 `chooseTarget` 里**重复**同一条件 | 条件写两遍，改一处漏一处 |
| 7 | 用了 `const` / 箭头函数 / `reduce` | 与全包其他技能的 ES5 风格不一致（无名杀主库为 ES5，扩展混入 ES6 会限制打包目标） |
| 8 | `ai:{threaten:4}` 只有威胁度，**无 `order` / `result`** | AI 不知道何时该发动，只能靠 `direct` 默认行为 |

**正确的重写方向**（保持行为不变）

```js
zhimeng:{
    audio:2,
    trigger:{ player:'phaseAfter' },
    direct:true,
    filter:function(event,player){                 // ← 条件只写一次，收敛到这里
        return game.hasPlayer(function(current){
            return current!=player && current.countCards('h')+player.countCards('h')>0;
        });
    },
    content:function(){
        'step 0'
        player.chooseTarget(get.prompt('zhimeng'),'与一名其他角色平分手牌')
            .set('filterTarget',function(card,player,target){    // ← 复用同一判据
                return target!=player && target.countCards('h')+player.countCards('h')>0;
            })
            .set('ai',function(target){ /* ... */ });
        'step 1'
        if(!result.bool){ event.finish(); return; }   // ← 显式 return，避免继续往下跑
        var t=result.targets[0];
        event.target=t;                                // ← 用引擎约定名，下一步可直接用 target
        event.tar=t;                                   // （如需保留旧名，别名即可）
        event.card=player.getCards('h').concat(t.getCards('h'));
        if(!event.card.length){ event.finish(); return; }
        event.num1=Math.ceil(event.card.length/2);     // ← 两分支合并为一行
        'step 2'
        player.logSkill('zhimeng',target);
        event.card1=event.card.randomGets(event.num1);
        event.card2=event.card.filter(function(i){ return !event.card1.contains(i); });
        player.gain(event.card1);
        target.gain(event.card2);
    },
    ai:{ order:3, threaten:4, result:{ player:1 } },   // ← 补齐 AI 声明
},
```

**从这个反例能提炼的三条通则**

1. **不要留注释掉的旧实现。** `parsex` 会剥注释，但**保留 `'step N'` 字面量的位置语义**；两套 step 并存是定时炸弹。要留旧版就改名（`zhimeng_old`）或挪到 `.bak`。
2. **自造 `event.xxx` 字段可以，但 `target` / `cards` 这类引擎约定名不要绕过。** 绕过它们等于放弃引擎的注入便利，且后来者无法预测。
3. **同一判据只写一遍。** `filter` 与 `chooseTarget.filterTarget` 应共享同一个具名函数。
