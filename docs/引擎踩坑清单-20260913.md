# 引擎踩坑清单（琉璃版 5.5 实测）

> 来源：2026-09-13 一次「三将（兵·诸葛亮 / 名·周瑜 / 名·裴秀）从零重写」的实战。
> 每条都是**当次实测**结论，附引擎依据或实测现象。写代码前先扫一遍这一页，

## 一、会把技能**静默弄死**的四件事（最危险，因为不报错）

### 1. `filter` 里不能用 `trigger`

`filter` 的形参只有 `(event, player)` —— **`trigger` 只存在于 `content`**
（引擎在 `game.js:15553` 设 `next._trigger`；`content` 里另有 `trigger` 注入）。

```js
// ✗ 错：抛 ReferenceError，被引擎吞掉 ⇒ filter 返回 undefined ⇒ 技能静默失效
filter: function (event, player) { return trigger.player == player; }
// ✓ 对：用 event
filter: function (event, player) { return event.player == player; }
```

实测代价：一轮改动里空城/情势全部失效，且游戏不报错、只是"什么都不发生"。

### 2. `filter` 里 `event.triggername` 往往是 `undefined`

实测气泡诊断输出：`evt=logSkill tn=undefined` —— 事件名在 `event.name` 上。
而 `content` 里的 `event.triggername` 是**可靠的**（引擎建技能事件时显式赋值）。
⇒ 分派一律写成：

```js
var tn = event.triggername;
if (tn == undefined) tn = event.name;
```

实测代价：按 `triggername` 分派的所有 filter 永远不成立 —— 表现为
"第一张牌能触发、第二张完全不评估"这类极难定位的症状。

### 3. 步骤号必须从 0 **连续**，且 `'step N'` 只能在**函数体顶层**

引擎把 `'step N'` 逐个替换成 `break;case N:`，**遇到第一个缺失编号就停止**
（`game.js:12106-12111`），末尾补一句 `if(event.step==K){event.finish();return;}`
（`game.js:12129`）。

- **编号断开** ⇒ 断点后的步骤没有 `case`，且末步守卫按错误的 K 生成、永不成立
  ⇒ `event.finish()` 永不执行 ⇒ `event.step` 无限增长、整段代码被反复执行
  ⇒ **整个游戏循环卡死**（实测：气泡显示 `引擎传step=169407` 且持续增长）。
- **`'step N'` 嵌在 `if/else` 里** ⇒ 替换成 `break;case N:` 时 break 落在块内、
  生成代码语法非法 ⇒ 该处替换被跳过 ⇒ 状态机错位（lint 报 `Unexpected token 'case'`）。
- **重号**同样会错位。

正确做法：**顶层判条件 + 步骤内分派**：

```js
'step 0'
if (event.name == 'damageBegin1') { event.mode = 'src'; player.chooseBool(...); return; }
event.mode = 'fire';  /* 另一条分支继续 */ player.chooseControl(...);
return;
'step 1'
if (event.mode == 'src') { /* 收尾 */ event.finish(); return; }
/* 另一条的收尾 */
```

### 4. `content` 的执行可靠性**参差**（本项目最坑的一条）

实测：某些技能的 `content` **从不执行**，而同文件里另一批技能的 `content` 正常。

- 不执行的例子：一个同时挂了 `enable: 'phaseUse'` 的锁定技，无论触发声明写成
  `player:'useCardBegin'` / `player:'useCard'` / `global:'useCard'` / `global:'useCardAfter'`，
  filter 都放行（能观测到"放行=1"），但 content 一次都没进去（无报错、无日志）。
- 正常的例子：`forced:true, locked:true, popup:false, direct:true` 的
  **全局静默追踪器**（`trigger:{global:[...]}`），其 content 确实在执行。

⇒ **设计对策**：把"看门/检测"职责集中到一个已验证会执行的静默追踪器上，
业务逻辑内联在它里面；不要指望每个技能自己的 content 都能跑。

## 二、内容层面的坑

### 5. "额外结算一次"要用引擎内置字段，别手动重放

原版「诗仙」（`collab.js:2556`）的做法：

```js
trigger: { player: 'useCard' },
content: function () { trigger.effectCount++; }     // 引擎自己多结算一次
```

- ✗ 手动 `player.useCard(同一张牌, ...)` 重放 ⇒ 那张牌又走一遍触发链 ⇒ **递归**
  （实测"一张锦囊用了三次"）。
- 时机：`effectCount` 必须加在 **useCard 事件**上；且"额外结算"要在牌**结算前**安排。

### 6. 去重时别比对象身份

"同一张牌的多次评估"里，**事件对象与牌对象都可能是新的**
（额外结算那一遍尤其如此）。可靠判据按优先级：

1. `useCard事件.effectCount > 0` ⇒ 这是额外结算那一遍（引擎自己的标记）
2. 状态位 + 明确的清零点（`init` 初始化、回合开始清零）

实测教训：按牌对象去重 ⇒ 同一张牌被算两次、把"每回合两次"的额度一次用光；
按事件对象去重 ⇒ 额外那遍是另一个事件对象，同样挡不住。

### 7. `mark: 'character'` 会和 UI 扩展冲突 ⇒ 用 `mark: true`

- 引擎在 `markSkill` 的 `'character'` 分支里把 `caption` 取自 **`info.name`**
  （`game.js:28227` 附近；而字段实际应读 `info.intro.name`）⇒ caption 为 `undefined`。
- 本作【十周年UI】重写了 `markSkillCharacter`，其 `markCharacter(name, info)` 只对
  **object** 做兜底（`if (typeof name == 'object') name = name.name;`），
  `undefined` 走不到兜底 ⇒ `name.indexOf('unknown')` 抛 TypeError ⇒ **选将阶段崩溃**。
- ⇒ 转换技/标记一律 `mark: true`（原版转换技就是 mark:true，见 `clan.js:569` 观骨）。

### 8. 转换技的正确接法（引擎原生）

| 要素 | 写法 | 依据 |
|---|---|---|
| 声明 | `zhuanhuanji: true` | `game.js:60267` 归入「转换技」 |
| 形态存放 | **`player.storage[技能名]`**（键名必须与技能同名） | `game.js:28208-28211`：引擎以 `storage[技能名]` 调用 `intro.content` |
| 统一翻转 | `player.changeZhuanhuanji('技能名')` | `game.js:22209-22218`：翻转 storage + 牌面翻转动画 + 刷新标记 |
| 是否阳面 | `zhuanhuanji2: function(skill, player){ return !!player.storage[技能名]; }` | `game.js:64963-64971` |
| 标记说明 | `mark: true` + `intro:{ name, content: function(storage){...} }` | 同上；`storage` 即当前形态 |

### 9. 自触发成环

带 `locked: true` 的技能，**它自己的发动也会派发 `logSkill`**。挂在 `logSkill` 上的
技能必须排除自己，否则"发动技能触发它 → 它自己也算发动技能 → 再触发"成环。

```js
filter: function (event, player) { return event.skill != '本技能名'; }
```

### 10. 摸牌/收牌类时机在开局前也会派发

`logSkill` 在 `gameStart` 之前同样会派发（初始化阶段各锁定技的自动触发都算）。
实测：某技能"发动技能摸牌"在开局就被喂了 7 张。判据用引擎自己的标志：

```js
if (!_status.gameStarted) return false;    // 引擎在 gameStart 时置位
```

### 11. 收牌/弃牌事件的结算要放到**下一个步骤**

`gain` / `discard` 是入队事件，**同一步内** `countCards()` 读到的还是旧值。
实测：判"手牌是否已空"写在同一步里 ⇒ 检测不到 ⇒ 技能不终止。

### 12. 临时技能不要当"计数闸门"

`addTempSkill` 的过期取决于过期表是否被登记过，实测会出现闸门没被清掉
⇒ 后续全被挡（表现为"只有第一次能触发"）。计数用 **storage + 明确清零点**。

## 三、诊断环境（本机实测）

| 通道 | 可用性 | 说明 |
|---|---|---|
| `player.say(msg)` 气泡 | ✅ | 角色头顶显示，**不需要控制台/文件**，最可靠 |
| `require('fs')` 写文件 | ✅ | `nodeIntegration:true`（`main.js:143`），可 `appendFileSync` |
| `game.log(...)` 战报 | ✅ | 右侧 `#sidebar` 面板，最新在最上 |
| `game.print(...)` | ✗ | 只进**游戏内置**开发者控制台队列（`game.js:52324`），用不上 |
| F12 控制台 | ✗ | 本机按不出来 |

**写盘失败必须回显**：曾用 `catch {}` 吞掉写入异常，误判"通道不通"，
白白浪费多轮往返。任何诊断通道的失败都要能被看见。

### 定位"卡死"的判据

在 `content`/`filter` 里打印 `引擎传step` 与 `event.step`：

- 两者**一致且持续增长** ⇒ `event.finish()` 没被调用 ⇒ **先查步骤号是否连续**
- 完全没有输出 ⇒ 该技能的 `content` 根本没被执行（见 §4）

## 四、改动流程上我自己踩的坑（避免重复）

| 事故 | 教训 |
|---|---|
| 用 PowerShell 的 `Get-Content -Raw` + `Set-Content -Encoding utf8` 改文件 | 写出 BOM/改行尾，`node --check` 直接语法错 ⇒ **文件内容一律用 read/edit/write 工具或临时 mjs 脚本** |
| 一次性替换**整张 `skill` 表** | 其他 6 个武将的技能全丢（lint 报 60 项悬空引用）⇒ 批量替换必须先算清"替换范围首尾"，并用技能名清单核对 |
| 替换范围多吃了表尾 | 结构差一层 ⇒ 替换后立刻 `node --check`；收尾用**大括号配对**定位，不假设缩进 |
| 备份来源搞混（用了旧版临时备份覆盖新工作树） | 还原前先确认"HEAD 是哪个版本"，别信任随手复制到 temp 的文件 |
| 新块行尾是 LF、原文件是 CRLF | 拼接后 `check-encoding` 报"混用行尾" ⇒ 拼接脚本里统一行尾 |
| 改完只看 `node --check` | 步骤号/嵌套/译名残缺都不报语法错 ⇒ 固定跑这一套：`renumber-steps` / `audit-step-nesting` / `audit-callback-scope` / `audit-dup-keys` / `lint-extension` / `mock-load` / `check-encoding` |
