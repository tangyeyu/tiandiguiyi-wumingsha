## 1. 步骤机制（当次对着本机 5.5 核实）

引擎把 `content` 函数编译成步骤机，两条分支：

| 分支 | 触发条件 | 位置 |
|---|---|---|
| `parsexOld` | `localStorage.finalParsex == 'old'` | game.js:12072-12090 |
| `Legacy` | 默认 | game.js:12094-12134 |

`Legacy` 的做法（关键）：

```js
// 1) 从 k=0 起逐个替换，遇到第一个不存在的编号就停
for (var k=0;k<99;k++) {
  var reg=new RegExp(`['"]step ${k}['"]`);
  var result=str.slice(skip).match(reg);
  if(result==null) break;                       // ★ 断点即终止
  var insertStr = k==0 ? `switch(step){case 0:` : `break;case ${k}:`;
  ...
}
// 2) 把 'step 0' 换成"末步守卫 + switch 开头"
str=`if(event.step==${k}){event.finish();return;}`+str;
```

主循环（game.js:41663 起，`game.loop`）：

- 读 `var step=event.step`（41665），以此调用 `event.content(event, step, …)`（41801）；
- content 返回后 `event.step++`（41806）；
- `event.step` 无上限，**唯一出口是 content 自己调 `event.finish()`**。

### 1.1 三条硬约束

1. **步骤号必须从 0 起连续**（0,1,2,…）。断号 ⇒ 断点后的步骤没有 `case`，
   且末步守卫按错误的 k 生成、永不成立 ⇒ `event.finish()` 永不执行
   ⇒ `event.step` 无限增长、同一段代码被反复执行 ⇒ **整个游戏循环卡死**。
2. **`content` 的形参只有**：`event, step, source, player, target, targets, card, cards,
   skill, forced, num, trigger, result, _status, lib, game, ui, get, ai`（game.js:12131-12133）。
   它是 `new Function` 编译的 —— **包级闭包里的局部变量在运行时看不到**。
3. `event.goto(n)` 语义是 `this.step = n-1`（game.js:31959-31961），
   之后主循环 `++` 落到 n。`goto` 在正常建起 switch 时可用；步骤号断了就没意义。

## 2. 症状 → 判据速查

| 症状 | 判据 | 结论 |
|---|---|---|
| 某武将轮到他即卡死 | 插桩打印 `引擎传step` 与 `event.step`，看是否**持续增长** | 增长 ⇒ `event.finish()` 没被调用 ⇒ 先查步骤号是否连续 |
| 技能"没反应" | 在 step 0 插一条气泡，看有没有出现 | 没出现 ⇒ content 压根没执行，问题在 trigger/filter |
| 分支里某段代码像没跑 | 该分支所在步骤的编号是否在断点之后 | 断点后的步骤没被编成 case |

## 3. 诊断手段的失败史（四次，全部是我的方法错误）

| 版本 | 做法 | 失败原因 |
|---|---|---|
| ① | 把工具函数 `trace` 声明在包级闭包，content 里调用 | content 由 `new Function` 编译 ⇒ **看不到闭包变量** ⇒ 游戏报 `ReferenceError: trace is not defined` |
| ② | 改用 `C:\bz-diag.log` 写文件，失败只 `catch {}` | **静默 catch 把失败原因吞了** ⇒ 用户只看到 `ENOENT`，我拿不到任何信息 |
| ③ | 汇总行插在末步 `event.finish(); return;` **之后** | 死代码：`node --check` 能过（语法合法），运行时**永远到不了** |
| ④ | 只解析"每次修正后的行号" | 读了**过期的临时产物**（补丁是分几次加上的），据此得出的结论全无效 |

教训：

- **插桩代码只能用 content 的形参**（`game`/`player`/`event`/`lib`…），不要用闭包局部变量；
- **诊断通道的失败必须回显**，禁止 `catch {}` 里什么都不做；
- **写完插桩先确认产物的字节真的变了**（行数/关键字计数），再谈结论；
- **不可达代码不会因为语法合法而报错** —— 位置必须落在"一定会执行到的入点"
  （例如末步的**开头**，而不是末步的 `finish/return` 之后）。

## 4. 通道可靠性排序（本机实测）

| 通道 | 可靠性 | 说明 |
|---|---|---|
| `player.say(msg)` | ★★★ | 角色头顶气泡，游戏自己绘制；本机 F12 打不开、战报面板也不好找时，这是唯一能用的 |
| 写文件 `require('fs')` | ★★ | 本作 Electron：`main.js:143-145` `nodeIntegration:true`/`contextIsolation:false` ⇒ 可用；但路径/权限会失败，**失败必须回显** |
| `game.log(...)` | ★★ | 进"战报"（右侧 `#sidebar`，game.js:54184；最新在最上 44423）；受 `lib.config.show_log` 影响 |
| `game.print(...)` | ✗ | 只往 `_status.toprint` 排队，由**游戏内置开发者控制台**消费（game.js:52324），本机用不上 |
| F12 控制台 | ✗ | 本机按不出来 |

`player.say` 有一个静默分支要注意：`game.js:23419`
`if(this!=game.me && lib.config.no_any_chat) return;` —— 非本人且关了闲聊时**什么都不显示**。

## 6. 步骤机错位清单（2026-09-13 扫描，**尚未修复**）

两个独立工具互为佐证：`renumber-steps.mjs`（按"编号是否连续"判）
与 `parsex-audit.mjs`（按"编译后是否残留 `'step N'`"判）。**两者都点名了 `mzy_fanjian`
与 `mzy_yingyan`**；后者还多报了三处 `Unexpected token 'case'`。

| 技能 | 步骤号 | 判定依据 | 风险 |
|---|---|---|---|
| `mzy_fanjian`（周瑜·反间） | 0,1,2,3,4,5,6,**8** | 跳过 7；`goto(8)` 目标不存在 | **高**：与"反间不终止"同源，且卡死风险 |
| `mzy_yingyan`（周瑜·映炎） | 0,1,**1**,2,3,4,5,6 | 重号 | **高**：错位后分支行为不可预测 |
| `mzy_shanmou`（周瑜·善谋） | 0,1 | `Unexpected token 'case'`（`old` 分支下硬崩） | 待复核 |
| `mzy_jichu`（周瑜·技出） | 0,1 | 同上 | 待复核 |
| `mpx_juezhi`（裴秀·爵制） | 0,1,2,3,4,5 | 残留 2 处 | 待复核 |

修法的注意点：重排会让 `goto` 的目标编号改变，`renumber-steps.mjs --apply`
会自动改写 `goto` 目标，但**改完必须逐个复核语义**（尤其 `mzy_fanjian` 的
`goto(8)`/`goto(6)`/`goto(3)` 三处循环回跳），不要盲改。
