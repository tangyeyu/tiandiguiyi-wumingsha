## 3. 范式与陷阱（速查）

### 3.1 「当任意牌名使用或打出」⇒ 照抄 spmiewu（shiji.js）
```
enable: ['chooseToUse','chooseToRespond']   // 数组必须含 'chooseToUse'（见事实1/2）
filter: 备>0 && 未用过 && lib.inpile 里有名字能过 event.filterCard
chooseButton: {
    dialog: 遍历 lib.inpile，event.filterCard({name:i},...) 逐名校验 ⇒ [list,'vcard']
    filter/check/backup(links)⇒{ viewAs:{name:links[0][2]}, precontent:扣费+temp标记 }
    prompt(links)
}
hiddenCard / ai.skillTagFilter：响应可用性判定用
```
坑：①sha 分支先推普通杀再推属性变体；②裸字符串数组会崩（事实4）；③扣费放
precontent，别放 content（viewAs 技能不走 content）。

### 3.2 「当你发动技能后」⇒ trigger `logSkill`
```
trigger: { player: 'logSkill' }   // event.skill = 技能 id
```
含锁定技自动触发；不含 popup:false 的静默内部技能（正好防自触发）。
响应器自身务必 popup:false + direct:true。

### 3.3 多时机合并式（技能栏瘦身）
```
trigger: { global:'roundStart', player:['phaseEnd','phaseUseBegin'] }
content: 按 event.triggername 分支
```
filter 也要按 triggername 分支（每时机各自的门槛）。enable+trigger 共存时，
phaseUse 按钮路径的 content 内 `event.triggername` 为 undefined。

### 3.4 「本回合限一次」⇒ precontent/content 置 temp 标记
`addTempSkill('xx_used')`（缺省回合结束过期），filter 查 `hasSkill('xx_used')`。
不要用 storage 手工记账（要自己找复位点）；mod 型常驻门槛用 storage+门控。

### 3.5 转换技简实现
不需要引擎特殊字段：storage 翻面 + 效果按面分支，初始阳面。
转换时机写清楚（"当你手牌数变为0或从0改变时"这类）。

### 3.6 取消语义
chooseControl 要可取消 ⇒ 控件里加 `'cancel2'` 并判 `result.control=='cancel2'`。
**禁止** `result.index` 回退 0 的写法。

### 3.7 多时机合并的边界（九伐事故）
带 `skillAnimation`（全屏扫屏动画）或非 forced（要弹"是否发动"）的技能，
**不能**并入静默追踪分支——合并后每次有人用/弃【杀】都会空放一次动画且无选项
（用户实测「一进游戏就技能进度条但没选项」）。静默追踪器保持独立子技能
（forced+direct+popup:false）。合并前先问：这个 trigger 的每个分支要不要
动画/询问/门槛一致？不一致就不合并。

## 5. 神威技接入清单（新武将含神威技时逐项打勾）

1. 技能 `init` 写 `player.storage.tdgx_sw[技能名] = 1`；
2. `filter` 查 `tdgx_sw[技能名] > 0`，`content` 开头自减；
3. `tdgx_shenwei_kill` 的 **filter 与 content 两处 list** 都要加技能名；
4. 该隐藏技 `tdgx_shenwei_kill` / `tdgx_turn_reset` **列进武将数组**；
5. 正文自带"每局限一次"字样的，按类别规则（最多2次）实现，正文视为赘述；
6. mod 型配件（如纵横/驰）**不进数组**，动态 addTempSkill/addSkill。
