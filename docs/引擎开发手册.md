### A. 静默失效 / 卡死的硬性禁止项

1. ❌ `filter` 里用 `trigger` → ✅ 形参是 `(event, player, name)`（三参，见 C 节第 3 条的**订正**），触发源在 `content` 里才叫 `trigger`（踩:13；契:202）。写成 `trigger` ⇒ ReferenceError 被吞 ⇒ filter 返回 undefined ⇒ 技能静默失效（踩:17-23）。
2. ❌ 用 `event.triggername` 分派 → ✅ filter 里它常是 `undefined`，先兜底 `var tn=event.triggername; if(tn==undefined) tn=event.name;`（踩:25-37；bug:17）。
3. ❌ 拿**触发键字符串**比 `event.name` → ✅ 伤害触发键 `damageBegin1..4` 但 `event.name` **恒为 `damage`**（阶段靠 `event.step`）；阶段键 `phaseJieshuBegin` 而 `event.name` 是 `phaseJieshu`；仅 `roundStart` 恰好一致（踩:156-181；bug:9-30）。
4. ❌ 在 `content` 里用 `event.name` 判触发事件 → ✅ `content` 的 `event` 是**技能自己的事件**（`event.name`=技能名），真事件在 `trigger.name`（踩:245-259；契:202）。
5. ❌ 步骤号跳号 → ✅ 必须从 0 **连续**；引擎替换循环遇第一个缺失编号即 `break`（踩:39-50；步:22-28；契:94-107）。
6. ❌ 把 `'step N'` 写进 `if/else/for` 或重号 → ✅ 一律函数体顶层；合法顶层缩进 8 tab，超出即违规（踩:48-50；步:44-50；契:69-77,128-130；范:581）。
7. ❌ `content` 里跨步用局部变量 / 直接读 `target` → ✅ 挂 `event.xxx` 跨步传值；用 `target` 前先 `event.target = result.targets[0]`（契:174-189,210-215）。
8. ❌ `content: function*` 或参数解构 → ✅ 只写 `content: function(){...}`；`old` 分支（疾速模式）无 try/catch，解构签名直接抛 `SyntaxError`（契:134-149；范:582-583）。
9. ❌ `content` 里引用包级闭包变量 → ✅ 就地展开；只有 `content`/`cost`/`onremove` 经 `new Function`，`filter`/`check`/`ai`/`init` 闭包完好（契:151-172）。
10. ❌ 注册 `loseAfter`/`equipAfter` 后判 `event.name=='loseAfter'` → ✅ 事件名仍是 `lose`/`equip`，只有**钩子名**带 After（踩:261-273）。
11. ❌ 用 `event.getl(player).es` 判失牌 → ✅ 本机实测 `es` 为空，须合并 `getl().es/hs/js` **并** `event.cards`（踩:275-286）。
12. ❌ 手动 `player.useCard()` 重放做"额外结算" → ✅ 只写 `trigger.effectCount++`，否则递归（踩:81-92）。
13. ❌ 按牌对象/事件对象身份去重 → ✅ 用 `useCard事件.effectCount>0` 或 status 位 + 明确清零点（踩:94-103）。
14. ❌ `mark: 'character'` → ✅ `mark: true`；`character` 分支的 caption 取错字段且十周年 UI 会对 `undefined` 抛 TypeError ⇒ 选将阶段崩溃（踩:105-112）。
15. ❌ 用 `addTempSkill` 当计数闸门 → ✅ storage + 明确清零点（踩:147-150；步:171-179）。
16. ❌ 关键 `mod` 挂在"不在武将数组里的子技能"上 → ✅ 并进始终存在的主技能（踩:223-228；bug:80-83）。
17. ❌ `audio` 写文件名 → ✅ 必须写**真实技能名**（或数字 N）；写文件名在 `game.js:37401` 处 `return` ⇒ 完全无声（踩:312-329）。

### B. `content` / `step` 编译契约

**编译流程**（契:48-57，`game.js:12070`）：取 `func.toString()` → 切掉第一个 `{` 之前（**签名整个丢弃**）→ `'step N'` 正则替换成 `break;case N:`（`game.js:12115`）→ 开头补 `switch(step){case 0:` → 末尾补 `if(event.step==K){event.finish();return;}`（K=末步+1）→ `new Function` 重建。

- **编号规则**：0,1,2… 连续、无跳号、无重号。不写 `'step 0'` 时引擎走另一分支：开头插 `if(event.step==1){event.finish();return;}`（`game.js:12102`）⇒ **单步技能可以不写 `'step 0'`，写了就必须连续**（契:64-65）。
- **能否写在 if/else 里**：**不能**。JS 禁止 `case` 出现在 `switch` 内嵌块（契:72-77）。`parsex` 有 try/catch 兜底（`game.js:12120-12127`）——**订正（实读 `game.js:12106-12128` + 本机实跑复现）**：失败时执行的是 `catch(error){ k--; skip += result.index + result[0].length; }`，即**跳过该处、以同一个编号继续找下一处同名标记**；找不到才 `break`。所以两个同名 `'step 1'` 时，**通过校验的那一个才成为 `case 1:`，另一个原样留成惰性字符串**（实测：嵌套那个被跳过，`case 1:` 落到了顶层那个 ⇒ 答完对话框后执行的是另一分支的代码、直接 `finish`，效果永不生效）。只有当该编号**所有**出现位置都过不了校验、且后面再没有同名标记时才退化（此时 `if(event.step==k)` 的 `k` 停在该编号）。多分支正确写法＝**顶层判条件 + 步骤内分派**（踩:52-62；步:51-62）。
- **为什么跳号卡死主循环**：主循环读 `var step=event.step`（`game.js:41665`）→ 调用 content（41801）→ 返回后 `event.step++`（41806）；`event.step` **无上限，唯一出口是 content 自己调 `event.finish()`**（步:33-37）。跳号 ⇒ K 停在断点 ⇒ 末步守卫恒不成立（`game.js:12129`）⇒ 同一段代码无限重复 ⇒ 实测 `引擎传step=169407` 且持续增长（契:92-107）。
- **parsex 与 Legacy 的差别**（步:13-16；契:136-149）——**订正（实读 `game.js:12070-12180` 与 `374`）**：`parsex` 先按 `typeof item` 分派，**只有普通函数**才落进两条编译分支：`parsexOld`（仅当 `localStorage.finalParsex=='old'`，即 UI 的**「疾速模式」**，`game.js:12072-12090`，无 try/catch）与 `Legacy`（默认分支，`game.js:12094-12134`，有 try/catch）。
  **generator 检测并不在 Legacy 里**，而在分派处 `game.js:12163-12180`：`if (gnc.is.generatorFunc(item))` 直接返回一个**协程驱动闭包**（内部 `gen=item(event,{…}); gen.next(…)`），**完全绕过 parsex 的 `'stepN'` 字符串改写**；`gnc.is.generatorFunc` 定义在 `game.js:374`。
  ⇒ 就引擎能力而言 generator 是**被支持的**；契:134-149 的「绝不写 generator」属**项目自定的保守约定**，不是引擎不支持。本仓库现状与该约定一致：`extension/extension.js` 中 `content: function*` **0 处**（2026-10-06 实地 grep）。心:25 那句「已改用 generator 写法」与当前文件不符，属**过期勘误**。
- **注入变量（19 个）**（契:193-205，`game.js:41666-41676` / 调用点 `41790`）：`event, step, source, player, target, targets, card, cards, skill, forced, num, trigger, result, _status, lib, game, ui, get, ai`。要点：`trigger=event._trigger`（主动技为 undefined）、`result`=上一步选择结果（无选择时为 undefined，读前必须判空）、`cards`=本事件自己的 `event.cards`。
- 步进控制：`event.finish()` / `event.goto(n)`（=`this.step=n-1`，`game.js:31959`）/ `event.redo()`（=`this.step--`，重跑当前步，须打在正确层级）/ `event.getParent(n)`（契:219-229）。改步骤号必须同步重映射 goto（步:68-70）。

### C. 触发键（trigger）

| 键 | 含义 | 引擎依据 |
|---|---|---|
| `player` | `event.player == player` | 契:244,246；心:283-284 |
| `source` | `event.source == player`（自己为伤害来源） | 契:246 |
| `target` | `event.target == player`（自己成为牌的目标） | 契:247 |
| `global` | 所有玩家均匹配，`(i=='global') \|\| event[i]==player` | 心:283-284 |

- 解析逻辑 `for (var i in info.trigger) if ((i=='global' \|\| player==event[i]) && has(...))` ⇒ **双键/数组完全合法**：`{global:'gameStart', player:'enterGame'}`、`{player:['damageEnd','recover']}`（心:274-287）。范:97-119 展示 `{player:..., target:...}` 双视角，`content` 里用 `player==trigger.player` 判断站哪一侧。
- `filter` 与 `content` 的分工：`filter` 里 `event` 是**真事件**（判 `event.name`）；`content` 里 `event` 是**技能自己的事件**，真事件是 `trigger`（踩:249-252；契:253-254 推论 12：`trigger.xxx` 是改伤害/追加目标的唯一入口）。
- **`filter` 的第三参数 `name`（订正，实读 `game.js:33031` / `33060`）**：六份文档均未记载它，但它**确实存在，且值就是当前命中的触发键名**：

  ```js
  filterTrigger:function(event,player,name,skill){ … if(info.filter&&!info.filter(event,player,name)){ return false; } }
  ```

  ⇒ `filter` 里**优先用第三参数 `name` 分派时机**，它比 `event.triggername` 可靠：`filter` 里的 `event` 是**真事件**，其 `triggername` 常为 `undefined`（踩:25-36；bug:17）。
  在 `content` 里则相反：`event` 是**技能事件**，`event.triggername` 由引擎显式赋值、可靠（踩:28）。
  本扩展的多时机锁定技就是靠 `name` 分派的：`mx_shenwei`（`equipAfter`/`useCardAfter`/`respondAfter` 三路）与 `mx_yulei`（`damageBegin2`/`damageSource`/`damageEnd`/`phaseBefore`/`phaseEnd` 五路）。

  > ⚠️ 本条在 2026-10-06 之前写的是「**不要依赖第三参数（无文档依据）**」——**那是错的**：依据在引擎源码里，不在文档里。按旧写法写的技能会退回 `event.triggername`（filter 里常为 undefined）而静默失效。
- 陷阱：`Begin`/`Before` 可 `.cancel()`，`End`/`After` 不能 —— 要在结算前干预必须挂 `Begin`/`Before`（契:250-251；范:284）。
- 陷阱：拼错事件名 ⇒ 注册照做、filter 永不调用、**零日志**（`atlas/tools/README.md:103` C8）。
- 陷阱：`useCardToTargeted` 是**逐目标**派发（多目标牌每个目标各一次，含使用者自己），**必须自己判"我是不是目标"**；`dieAfter` 的击杀者用 `event.source` 而非 `event.player`（bug:97-101）。
- 陷阱：`logSkill` 在 `gameStart` 之前也会派发 ⇒ 用 `if(!_status.gameStarted) return false;`（踩:133-140）；挂 `logSkill` 的技能要排除自己防成环（踩:124-131）。

### D. 子技能（sub）注册要求

- **为什么必须列进武将数组**：触发链 `game.trigger(event)`（`game.js:32310`）→ 从 `lib.hook` 桶取技能（`addSkillTrigger` `27805`）→ `arrangeTrigger` 过滤（`15276`）→ `filterTrigger`（`33031`）→ **`player.getSkills(false).contains(skill)`（`33042~33044`）**；`!fullskills.contains(skill)` 即**直接跳过**。`lib.character[3]` 循环 `addSkill` 才把技能挂上身（`23092`）（心:250-272；踩:223-228）。后果：技能不在身上 ⇒ `mod` 永不生效（踩:226-228）。
- **隐藏方式**：子技能加 `sub:true` + `popup:false` + `charlotte:true`（或 `silent:true` 自动补全）；选将界面 `getStockSkills`（`24007`）过滤 `sub`/`charlotte`，不显示但功能正常（心:271-272；契:284）。
- **`subSkill` 自动派生**：`subSkill:{mark:{...}}` → 自动派生 `父技能_mark`、强制 `sub=true`、翻译继承父技能（`game.js:44153`，契:276）。但它的注册只在 `finishCards()`（`game.js:44283`，启动时遍历全部技能）里跑，扩展若在开局后才导入，主技能可能没被 `finishSkill` 处理过 ⇒ 子技能未注册 ⇒ `addSkill` 时 `lib.skill[子技能名]` 不存在 ⇒ **直接 return（`game.js:28177-28178`）静默失败**（心:289-301）。作者结论：**不依赖 subSkill 自动注册**，把子技能写成顶层技能、各自 `sub:true`（心:289-301）。
- **`mark` / `marktext` / `intro`**：六份文档**均未出现 `marktext`**（已逐文件核验，0 命中）。已记载的是：`markSkill` 在 `lib.skill[标记名].intro` 缺失时**直接 return**（`game.js:27412-27417`）⇒ 头像上什么都不显示；角标文字另取 `<标记名>_bg` 译名（`game.js:27584`）⇒ 每个标记要补一个含 `intro` 的纯显示空壳 + `<标记名>_bg` 译名（心:419；`atlas/tools/README.md:101` C6）。仅做记账的裸标记**故意不给 `intro`** 即可隐藏（心:384-386）。
- `addMark` 只能存数字（或数组，`countMark` 返回长度），存非数字 ⇒ `countMark` 返回 0、`hasMark` 恒 false；`storage` 可存任意值但**须手写 `game.log` 与 `game.addVideo('storage',...)`**（范:511-522）。
- **跨文档冲突**：踩:105-112 与步:142-145 对 `mark:'character'` 说法不同（前者"与 UI 冲突 ⇒ 用 `mark:true`"，后者在转换技表里写 `mark:'character'`+`intro`）。判断依据：踩:108-111 给出了十周年 UI 重写 `markSkillCharacter` 的具体崩溃路径（`name.indexOf('unknown')` TypeError ⇒ 选将阶段崩溃），是更强的实证；故**本项目一律 `mark:true` + `intro:{name, content}`**。

### E. 常用范式速查（最小骨架要点）

- **主动技 + 选择一项**：`player.chooseControl(list)` 结果在 `result.control`；`player.chooseBool(...)` 结果在 `result.bool`（契:328-329）。两者都**必须判空**：若上一步没创建选择事件，引擎直接进下一步，`result` 是 `undefined` ⇒ 要写三重判空 `result.bool && result.targets && result.targets.length`（范:287-290）。"每回合四选一"：先按标记组装"还能添加的选项"，再 `chooseControl(labels)` 弹一次（心:387-391）。
- **`filter` vs `check`**：客观数值/状态门槛 → `filter`（硬门槛，条件不满足**技能不点亮**）；主观取舍 → `check`（人类**仍会被询问**）（契:256-264；范:334-345）。把主观判断写进 `filter` = 人类被 AI 绑架。
- **转化牌（chooseButton + backup）**：`sourceSkill:'aocai'`（防递归/日志归类）＋ `precontent`（独立状态机，在使用结算**之前**执行，可有自己的 `'step N'`）＋ `delete event.result.skill`（否则下游 `get.is.converted` 判定全错）＋ `event.result.cards=cards`（补实体牌）＋ `get.autoViewAs(...)`＋ **`filterCard:()=>false` 与 `selectCard:-1` 必须成对**（缺一即卡在选择界面或仍列可选牌）（范:362-397）。选实体牌用 `chooseCardButton`；`'vcard'` 的 list 必须是 `[type,suit,name]` 数组（bug:40-53）。
- **临时技 `addTempSkill`**：**不可**当"每回合闸门/计数器"（实测"只有第一张牌能触发"）⇒ 计数用 `storage` + 明确清零点（`init` 初始化 + `phaseBegin` 清零 + 用后落闸）；临时技只用于真正的 mod 型配件（踩:147-150；步:171-179）。
- **每回合限一次记账**：`usable: 1` 是引擎的出牌阶段限一次字段（契:368）；计数用 `player.addMark(s, n, log)`（第三参 `false` 不记日志）/ `countMark(s)` / `hasMark(s)`（契:332-333）。语义坑：卡面"限一次"限制的是**添加**次数而非发动次数（心:394-397）。
- **限定技 / 觉醒技**：`limited:true` 引擎自动补 `intro.content='limited'`、`skillAnimation=true`、`init: storage[skill]=false`（`game.js:44148-44151`）；`content` **第一行**必须 `player.awakenSkill('名字')`，它第 4 步 `if(this.storage[skill]===false) this.storage[skill]=true` **只在初值为 false 时生效**（范:177-189）。`juexingji:true`（标签）与 `awakenSkill()`（执行退役）**两个都写才算正确**（范:228-237；契:294-296）。
- **前置取消**：挂 `phaseDrawBefore` 而非 `phaseDrawEnd`，`trigger.cancel()` 取消该阶段本身；跨步存牌写 `event.cards=get.cards(2)`（注入变量 `cards` 每步重读 `event.cards`）（范:284-287）。
- **额外出牌阶段（不摸牌）**：`var next=player.phaseUse(); event.next.remove(next); trigger.next.push(next);` —— 挂 `trigger.getParent().next` 会排到**整个回合之后**（心:303-351）。
- **`mod`**：查询钩子表不是事件，引擎在需要判断时调 `game.checkMod(...)` 按名字取 `info.mod[name]`（`game.js:44285`、`44298`）；**必须纯查询、不能有副作用**（不能 `draw`、不能改 storage），它会被高频调用（范:426-450）。空壳子技能只写 `{charlotte:true, sub:true}` 当状态位（范:433-434）。

### F. 诊断通道

按可靠性排序（踩:345-353；步:103-114）：

1. `player.say(msg)` 气泡 ★★★ —— 角色头顶显示，不需要控制台/文件，最可靠。静默分支：`game.js:23419` `if(this!=game.me && lib.config.no_any_chat) return;` ⇒ 非本人且关了闲聊时**什么都不显示**（步:113-114）。
2. 写文件 `require('fs').appendFileSync` ★★ —— 本作 Electron `nodeIntegration:true`/`contextIsolation:false`（`main.js:143-145`），可用；路径/权限会失败，**失败必须回显**。注意：`content`/`filter` 由 `new Function` 编译，**严格模式下 `require` 不是自由变量** ⇒ 写文件要走挂在 `game` 上的 helper（`game.lib.bzDiag2`）（bug:118）。
3. `game.log(...)` 战报 ★★ —— 右侧 `#sidebar`（`game.js:54184`，最新在最上 `44423`），受 `lib.config.show_log` 影响；**战报不落盘，作者读不到**（bug:112-116）。
4. `game.print(...)` ✗ —— 只进 `_status.toprint` 队列，由**游戏内置**开发者控制台消费（`game.js:52324`），用不上。
5. F12 控制台 ✗ —— 本机按不出来。

**陷阱**：

- **必须双通道**：`game.log(...)` **和** `require('fs').appendFileSync(...)` 同时写（只写文件用户看不到；只写战报作者读不到）（踩:230-236；bug:112-116）。
- **"游戏没完全重启"会吃掉所有诊断**：进程未重启则加载的仍是旧代码，表现为"部署了带诊断的版本，日志为空"⇒ 测前先确认日志里有开机自检那一行（`【开机自检】版本=…`）（bug:121-125）。
- **不要用 `catch {}` 吞异常**：曾据此误判"通道不通"，白跑多轮（踩:355-356；步:89）。
- **插桩只用 content 的形参**（`game`/`player`/`event`/`lib`…），不要用闭包局部变量（步:88,95）。
- **位置必须落在一定会执行的入点**：汇总行写在末步 `event.finish(); return;` **之后** = 死代码，语法合法但永远到不了（步:90,98-99）。
- **把诊断放 filter 最前面**（任何 return 之前）做"无条件诊断"，一次就分清"filter 没被调用"与"条件不满足"（bug:132-135）。
- 卡死判据：打印 `引擎传step` 与 `event.step`，**一致且持续增长** ⇒ `event.finish()` 没被调用 ⇒ 先查步骤号连续性；**完全没有输出** ⇒ 该技能 `content` 根本没执行（踩:358-363；步:76-80）。
- 诊断插桩只应存在于**游戏目录的部署副本**，不要提交进仓库；还原用 `node atlas/tools/bz-diag.mjs off`（步:130-131）。

### G. 语音（audio）解析链

> 本节全部出自 **2026-10-06 实读** `resources/app/game/game.js:37356-37417`（另有阵亡音 `21124-21133`）。
> 六份文档对这块只有一句「`audio` 必须写真实技能名」（踩:312-329）——够用，但漏了下面第一条这个坑。

**入口**：`game.trySkillAudio(skill, player, directaudio, forceTaixu)`（`37356`），引擎在技能发动时调用；
`filter` 与 `content` 都可以自己调它（自己调就是「手动补一次语音」）。

- **`37361 if(info.direct&&!directaudio) return;`** —— **`direct:true` 的技能，引擎不会自动播音频**。
  这是「只有主动技出声、发动型技能没声音」的根因。修法是在**真正生效的那个分支**里调
  `game.trySkillAudio('<技能名>', player, true)`；落点必须逐个对着分支核，写在 `filter` 或没走到的
  分支里等于没写。官方同类用法：`character/yijiang.js:13214 game.trySkillAudio('xiansi2',event.target,true)`。

**解析步骤**（`37371` 起，逐行）：

| 行 | 规则 |
|---|---|
| `37371-37372` | `audioname = skill`（**起点是技能名本身**，不是 `audio` 的值）、`audioinfo = info.audio` |
| `37374-37377` | 若 `info.audioname2[player.name]` 命中，改用它 |
| `37382-37386` | `audioinfo` 是**字符串且 `lib.skill[它]` 存在** ⇒ 解引用到那个技能（可嵌套；`history` 防环） |
| `37387-37392` | 是**数组** ⇒ `audioname=audioinfo[0]`、`fixednum=audioinfo[1]`，再去解引用 `lib.skill[audioname].audio`。⚠️ **这里对 `lib.skill[audioname]` 没有判空** —— 数组第一项写一个不存在的技能名会直接 **TypeError**（比字符串写错更危险：字符串写错只是静默） |
| `37395-37398` | 若**原技能**的 `info.audioname` 是数组且含 `player.name/name1/name2` ⇒ `audioname += '_' + 那个名字` |
| `37400-37401` | `audioinfo` 是字符串且**不以 `ext:` 开头** ⇒ **`return`（静默无声）** |
| `37404-37409` | `ext:` 形式 ⇒ `playAudio('..','extension', 路径, audioname[+序号])`（音频随扩展走，`ext:...:true` 表示不随机） |
| `37412-37414` | `audioinfo` 是**数字 N** ⇒ `playAudio('skill', audioname + ceil(N*random()))`（即 `audio/skill/<audioname><1..N>.mp3`） |
| `37417` | 以上都不是、且 `info.audio !== false` ⇒ `playSkillAudio(audioname)`（兜底：把 `audioname` 当音频名用） |

- ⇒ **`audio` 要么写「真实存在的技能名」，要么写数字 N**；写文件名会落到 `37401` **静默无声**（A-17）。
- ⚠️ **扩展角色的 `audioname` 后缀陷阱**：`37396` 拼的是 `player.name`，而扩展角色的 id 是
  `tdgx_lukang` 这种**带前缀的名字**。照抄游戏里 `rejizhi` 的写法（`refresh.js:12286`
  `rejizhi:{audio:2, audioname:['lukang','xin_shen_simayi']}`）给扩展角色用，拼出来的是
  `rejizhi_tdgx_lukang.mp3` —— 磁盘上没有这个文件。
  要在扩展里复现「`<基础名>_<角色名>.mp3`」这套命名，只能用**桩技能**：加一个只带 `audio:N` 的空壳技能、
  名字就叫那个带后缀的全名，再让 `audio` 指向它（`37382` 那条字符串解引用会命中它）。
- **阵亡音**来自角色 `[4]` 标签：`21124-21133` 读 `die:<路径>` → `game.playAudio(path)`。
  `playAudio('die','shen_machao')` 与 `playAudio('die/shen_machao')` 拼出的字符串相同，两种写法等价。
- **自检**：`tools/verify-audio.mjs` —— 词法扫描扩展里每个 `audio:'…'`，逐个核实
  「是技能名？→ 该技能的 `audio` 字段是几？→ 对应 mp3 在磁盘上存在吗？」，并顺带查 `die:` 标签。
  反例（把旧版跑一遍）必须 FAIL，否则是验证器坏了。

## 引擎踩坑清单（琉璃版 5.5 实测）

> 来源：2026-09-13 一次「三将（兵·诸葛亮 / 名·周瑜 / 名·裴秀）从零重写」的实战。
> 每条都是**当次实测**结论，附引擎依据或实测现象。写代码前先扫一遍这一页，
> 能避掉绝大多数"改了没反应 / 改了更坏"的情况。

### 一、会把技能**静默弄死**的四件事（最危险，因为不报错）

#### 1. `filter` 里不能用 `trigger`

`filter` 的形参只有 `(event, player)` —— **`trigger` 只存在于 `content`**
（引擎在 `game.js:15553` 设 `next._trigger`；`content` 里另有 `trigger` 注入）。

```js
// ✗ 错：抛 ReferenceError，被引擎吞掉 ⇒ filter 返回 undefined ⇒ 技能静默失效
filter: function (event, player) { return trigger.player == player; }
// ✓ 对：用 event
filter: function (event, player) { return event.player == player; }
```

实测代价：一轮改动里空城/情势全部失效，且游戏不报错、只是"什么都不发生"。

#### 2. `filter` 里 `event.triggername` 往往是 `undefined`

实测气泡诊断输出：`evt=logSkill tn=undefined` —— 事件名在 `event.name` 上。
而 `content` 里的 `event.triggername` 是**可靠的**（引擎建技能事件时显式赋值）。
⇒ 分派一律写成：

```js
var tn = event.triggername;
if (tn == undefined) tn = event.name;
```

实测代价：按 `triggername` 分派的所有 filter 永远不成立 —— 表现为
"第一张牌能触发、第二张完全不评估"这类极难定位的症状。

#### 3. 步骤号必须从 0 **连续**，且 `'step N'` 只能在**函数体顶层**

引擎把 `'step N'` 逐个替换成 `break;case N:`，**遇到第一个缺失编号就停止**
（`game.js:12106-12111`），末尾补一句 `if(event.step==K){event.finish();return;}`
（`game.js:12129`）。

- **编号断开** ⇒ 断点后的步骤没有 `case`，且末步守卫按错误的 K 生成、永不成立
  ⇒ `event.finish()` 永不执行 ⇒ `event.step` 无限增长、整段代码被反复执行
  ⇒ **整个游戏循环卡死**（实测：气泡显示 `引擎传step=169407` 且持续增长）。
- **`'step N'` 嵌在 `if/else` 里** ⇒ 替换成 `break;case N:` 时 break 落在块内、
  生成代码语法非法 ⇒ 该处替换被跳过 ⇒ 状态机错位（lint 报 `Unexpected token 'case'`）。
- **重号**同样会错位。

正确做法：**顶层判条件 + 步骤内分派**：

```js
'step 0'
if (event.name == 'damageBegin1') { event.mode = 'src'; player.chooseBool(...); return; }
event.mode = 'fire';  /* 另一条分支继续 */ player.chooseControl(...);
return;
'step 1'
if (event.mode == 'src') { /* 收尾 */ event.finish(); return; }
/* 另一条的收尾 */
```

#### 4. `content` 的执行可靠性**参差**（本项目最坑的一条）

实测：某些技能的 `content` **从不执行**，而同文件里另一批技能的 `content` 正常。

- 不执行的例子：一个同时挂了 `enable: 'phaseUse'` 的锁定技，无论触发声明写成
  `player:'useCardBegin'` / `player:'useCard'` / `global:'useCard'` / `global:'useCardAfter'`，
  filter 都放行（能观测到"放行=1"），但 content 一次都没进去（无报错、无日志）。
- 正常的例子：`forced:true, locked:true, popup:false, direct:true` 的
  **全局静默追踪器**（`trigger:{global:[...]}`），其 content 确实在执行。

⇒ **设计对策**：把"看门/检测"职责集中到一个已验证会执行的静默追踪器上，
业务逻辑内联在它里面；不要指望每个技能自己的 content 都能跑。

### 二、内容层面的坑

#### 5. "额外结算一次"要用引擎内置字段，别手动重放

原版「诗仙」（`collab.js:2556`）的做法：

```js
trigger: { player: 'useCard' },
content: function () { trigger.effectCount++; }     // 引擎自己多结算一次
```

- ✗ 手动 `player.useCard(同一张牌, ...)` 重放 ⇒ 那张牌又走一遍触发链 ⇒ **递归**
  （实测"一张锦囊用了三次"）。
- 时机：`effectCount` 必须加在 **useCard 事件**上；且"额外结算"要在牌**结算前**安排。

#### 6. 去重时别比对象身份

"同一张牌的多次评估"里，**事件对象与牌对象都可能是新的**
（额外结算那一遍尤其如此）。可靠判据按优先级：

1. `useCard事件.effectCount > 0` ⇒ 这是额外结算那一遍（引擎自己的标记）
2. 状态位 + 明确的清零点（`init` 初始化、回合开始清零）

实测教训：按牌对象去重 ⇒ 同一张牌被算两次、把"每回合两次"的额度一次用光；
按事件对象去重 ⇒ 额外那遍是另一个事件对象，同样挡不住。

#### 7. `mark: 'character'` 会和 UI 扩展冲突 ⇒ 用 `mark: true`

- 引擎在 `markSkill` 的 `'character'` 分支里把 `caption` 取自 **`info.name`**
  （`game.js:28227` 附近；而字段实际应读 `info.intro.name`）⇒ caption 为 `undefined`。
- 本作【十周年UI】重写了 `markSkillCharacter`，其 `markCharacter(name, info)` 只对
  **object** 做兜底（`if (typeof name == 'object') name = name.name;`），
  `undefined` 走不到兜底 ⇒ `name.indexOf('unknown')` 抛 TypeError ⇒ **选将阶段崩溃**。
- ⇒ 转换技/标记一律 `mark: true`（原版转换技就是 mark:true，见 `clan.js:569` 观骨）。

#### 8. 转换技的正确接法（引擎原生）

| 要素 | 写法 | 依据 |
|---|---|---|
| 声明 | `zhuanhuanji: true` | `game.js:60267` 归入「转换技」 |
| 形态存放 | **`player.storage[技能名]`**（键名必须与技能同名） | `game.js:28208-28211`：引擎以 `storage[技能名]` 调用 `intro.content` |
| 统一翻转 | `player.changeZhuanhuanji('技能名')` | `game.js:22209-22218`：翻转 storage + 牌面翻转动画 + 刷新标记 |
| 是否阳面 | `zhuanhuanji2: function(skill, player){ return !!player.storage[技能名]; }` | `game.js:64963-64971` |
| 标记说明 | `mark: true` + `intro:{ name, content: function(storage){...} }` | 同上；`storage` 即当前形态 |

#### 9. 自触发成环

带 `locked: true` 的技能，**它自己的发动也会派发 `logSkill`**。挂在 `logSkill` 上的
技能必须排除自己，否则"发动技能触发它 → 它自己也算发动技能 → 再触发"成环。

```js
filter: function (event, player) { return event.skill != '本技能名'; }
```

#### 10. 摸牌/收牌类时机在开局前也会派发

`logSkill` 在 `gameStart` 之前同样会派发（初始化阶段各锁定技的自动触发都算）。
实测：某技能"发动技能摸牌"在开局就被喂了 7 张。判据用引擎自己的标志：

```js
if (!_status.gameStarted) return false;    // 引擎在 gameStart 时置位
```

#### 11. 收牌/弃牌事件的结算要放到**下一个步骤**

`gain` / `discard` 是入队事件，**同一步内** `countCards()` 读到的还是旧值。
实测：判"手牌是否已空"写在同一步里 ⇒ 检测不到 ⇒ 技能不终止。

#### 12. 临时技能不要当"计数闸门"

`addTempSkill` 的过期取决于过期表是否被登记过，实测会出现闸门没被清掉
⇒ 后续全被挡（表现为"只有第一次能触发"）。计数用 **storage + 明确清零点**。

### 二之二、本轮（2026-09-24）新踩的四个坑

#### 5.5 ★★ 触发键 ≠ 事件名（本轮最贵的坑，连害两处）★★

**在 `filter` / `content` 里分派时，绝不能拿"触发键字符串"去比 `event.name`。**

| 场景 | 触发键（写在 `trigger:` 里） | `event.name` 实际是 |
|---|---|---|
| 伤害四阶段 | `damageBegin1` … `damageBegin4` | **恒为 `damage`**（阶段看 `event.step`） |
| 阶段开始/结束 | `phaseJieshuBegin`、`phaseBegin` … | **`phaseJieshu`**（不带 `Begin`） |
| 回合开始 | `roundStart` | `roundStart` ✅（这个恰好一致） |

实测代价（各白改 1~2 轮）：

```js
// ✗ 恒为假 ⇒ 加伤永不生效
trigger: { source: 'damageBegin2' },
filter: (e) => e.name == 'damageBegin2'

// ✗ 恒为假 ⇒ 回合结束结算永不进入
filter: (e) => e.name == 'phaseJieshuBegin'

// ✓ 伤害阶段：直接用触发键，且只挂一个（多挂会重复叠加）
trigger: { source: 'damageBegin4' },  content: () => { trigger.num++ }

// ✓ 阶段：比 event.name（不带 Begin）
filter: (e) => e.name == 'phaseJieshu'
```

**判定方法**：怀疑时打印 `event.name` 与 `event.step`。本轮就是靠一行诊断定死的：
`事件=damage step=1 num=1` → `加9：1→10` → … → `step=5`（挂 5 个时机 ⇒ 加到 46）。

#### 5.6 一个技能不能同时做"主动发动"和"时机触发"

```js
// ✗ 引擎视作同一技能 ⇒ 时机到来时会走"主动发动"那条 content
gy_po_di: {
    enable: 'phaseUse',                        // 主动发动
    trigger: { player: 'phaseJieshuBegin' },    // 回合结束结算
    content: function () { if (event.name == 'phaseJieshu') { 结算 } else { 发动 } }
}
// 实测症状：**回合结束自动触发了这个技能**（弹出选目标对话框），结算从不执行。

// ✓ 拆成两个技能：一个只 enable，一个只 trigger，各管一件事
```

#### 5.7 `'s'` 区 = "放在**手牌容器**里的牌" ⇒ 会被当可用牌

`loseToSpecial` 最后走 `directgains`（`game.js:25965-25993`）：

```js
cards[i].classList.add('glows');
addLast(cards[i], this.node.handcards1);     // ← 追加进手牌区 DOM
```

`get.position` 的判定（`game.js` 内）：

```
parentNode.classList.contains('expansions')  → 'x'   （武将牌上的牌区）
parentNode.classList.contains('handcards')   → 's'（带 glows）/ 'h'
parentNode.id == 'special'                   → 's'
```

⇒ `getCards('s')` **同时**匹配"手牌容器里的 glows 牌"与"ui.special 的牌"，
两者都会被引擎当**可用牌**（用户实测"显示在手牌区且可以直接用"）。

**想要"看得见但不能直接用"** ⇒ 用 `addToExpansion(cards, player, tag)`
（进 `player.node.expansions`，独立容器）。

#### 5.8 mod 必须挂在"技能确实在身上"的技能上

`mod.cardUsable` 等只在**技能存在**时生效。挂在子技能上、而那个子技能**不在武将数组里**
⇒ 技能不在身上 ⇒ **mod 永不生效**（"杀不计入次数限制"失效的真因）。
引擎侧确实会走 mod：`game.js:28965 getCardUsable → checkMod(..., 'cardUsable', ...)`。
⇒ 关键 mod 一律并进**始终存在的主技能**。

#### 5.9 诊断必须**双通道**（战报 + 文件）

- 只写文件 ⇒ 用户看不到（且游戏没重启时旧代码不写，文件常常是空的）
- 只写战报 ⇒ **作者读不到**（战报不落盘）
- ⇒ 一律 `game.log(...)` **和** `require('fs').appendFileSync(...)` 同时写

另外：**用户说"好了"可能是"我测完了"** —— 要按"我去看数据"处理，不要当成结论。

### 二之三、本轮（2026-09-24~25，名·赵云）新踩的坑

> 本轮代价最大：**同一个"马离场摸两张"改了 6 轮**，根因是下面 5.10~5.12 三条叠加。
> 共同教训：**先用诊断把"引擎给我的数据"打出来，再改逻辑**。

#### 5.10 ★★★ `content` 里的 `event` 是**技能自己的事件**，真事件在 `trigger` ★★★

这是本轮最贵的一条，**与 `filter` 的语义相反**：

| 位置 | `event` 指向 | 判断触发事件应写 |
|---|---|---|
| `filter(event, player)` | **真事件** | `event.name == 'xxx'` |
| `content` | **技能自己的事件**（`event.name` = 技能名） | **`trigger.name == 'xxx'`** |

实测诊断（决定性证据）：
```
攻马·content入口 event.name=zyyi_horse_atk｜event===trigger? false｜trigger.name=damage
                   ↑ 技能名，不是触发事件            ↑ 两者不是同一对象
```
⇒ content 里写 `if (event.name == 'lose')` **恒为假** ⇒ 分支永不执行。

#### 5.11 ★★ `event.name` 是 `'equip'` / `'lose'`，**不是** `'equipAfter'` / `'loseAfter'` ★★

引擎通用派发（`game.js:41719`）：
```js
else if(event._triggered==3){
    if(event.type=='card') event.trigger('useCardToAfter');
    event.trigger(event.name+'After');      // 用「事件名+'After'」作为**钩子名**去派发
}
```
⇒ **事件本身的名字不变**（仍是 `equip` / `lose`），只有**钩子名**带 After。
⇒ 注册侧写 `player:'loseAfter'` 是对的，但 `filter` 里要判 `event.name == 'lose'`。

实测诊断：`攻马·filter 事件=lose` / `防马·filter 事件=equip`。

#### 5.12 ★★ `event.getl(player).es` 实测**为空** —— 失牌清单要用 `event.cards` ★★

原版技能确实写 `var evt=event.getl(player); if(!evt.es.length) return false;`
（`yingbian.js:1985`、`xinghuoliaoyun.js:529`），**但在这台引擎上 `es` 拿不到东西**：

```
攻马·lose明细 es=空｜hs数=1｜js数=0｜event.cards=dawan/equip4
                              ↑ 那张装备马被算在**手牌区**里
```
⇒ `!evt.es.length` 恒真 ⇒ 分支永不触发（**既不摸牌，又继续往下走伤害分支去弹框**）。
修法：失牌清单合并 `getl().es/hs/js` **并** `event.cards`（引擎 `lose:function` 里
`next.cards=arguments[i]`，`game.js:26203/26206`），逐个判 `get.subtype`。

#### 5.13 ★★ 兜底钩子比事件钩子可靠：`player.equip` / `player.lose` ★★

当事件链反复对不上时（5.10~5.12 那种叠加），**直接包装 `lib.element.player` 上的方法**：

```js
var _orig = lib.element.player.lose;
lib.element.player.lose = function () {
    var r = _orig.apply(this, arguments);
    // 这里可以拿到 arguments[0] = 失去的牌 ⇒ 判 get.subtype 后做效果
    return r;
};
```
本轮用它救活了"马上马下"与"马离场摸两张"（`equipAfter` 事件**实测根本不派发**，
全靠 `player.equip` 兜底置位）。**代价**：与事件时机解耦，需自己防重复结算（用 storage 闸门）。

#### 5.14 伤害数值要在 `damageBegin4` 改，且**跨事件传值要用 storage**

- `damage` 事件分 5 步（`game.js:20756-20811`）：
  `step0 damageBegin1 / step1 damageBegin2 / step2 damageBegin3 / step3 damageBegin4 / step4 实际结算`
  ⇒ 挂在 `damageBegin2` 弹框会比"伤害真正发生"早好几步（用户观感"还没打就弹"）；
  **`num` 到 step4 才被使用 ⇒ 在 `damageBegin4` 改 `num` 或 `cancel()` 仍然有效**。
- 跨事件传自定义值（`useCard` → `damage`）**不要挂在事件对象上**：
  实测 `uc._zycfX` 在 damage 侧取到 `null`。**改用 `player.storage`**（本轮摧锋·决的伤害值就这样传递）。

#### 5.15 `audio` 字段的形态语义（字符串会被**直接丢弃**）

`trySkillAudio`（`game.js:37356-37417`）：
```js

while (true) {                                    // 循环"解引用"
    if (typeof audioinfo=='string' && lib.skill[audioinfo]) { audioname=audioinfo; audioinfo=lib.skill[audioname].audio; continue; }

if (typeof audioinfo=='string') { if (audioinfo.indexOf('ext:')!=0) return; ... }   // ← 普通字符串在这里 return
```

  `Cannot read properties of undefined (reading 'audio')`）。写成**文件名**（如 `'wuyi_sha'`）
  ⇒ 循环解引用失败 ⇒ 落到 `37401` 的 `return` ⇒ **完全无声**。

  想给一组技能共用语音池 ⇒ 建一个**只承载语音的伞技能**，文件名按伞技能 id 命名。

#### 5.16 立绘"出框"有现成开关：`No_Outcrop`

引擎内建（`game.js:8828-8870`，注释「需添加'No_Outcrop'属性」）：

### 1. 步骤机制（当次对着本机 5.5 核实）

引擎把 `content` 函数编译成步骤机，两条分支：

| 分支 | 触发条件 | 位置 |
|---|---|---|
| `parsexOld` | `localStorage.finalParsex == 'old'` | game.js:12072-12090 |
| `Legacy` | 默认 | game.js:12094-12134 |

`Legacy` 的做法（关键）：

```js
// 1) 从 k=0 起逐个替换，遇到第一个不存在的编号就停
for (var k=0;k<99;k++) {
  var reg=new RegExp(`['"]step ${k}['"]`);
  var result=str.slice(skip).match(reg);
  if(result==null) break;                       // ★ 断点即终止
  var insertStr = k==0 ? `switch(step){case 0:` : `break;case ${k}:`;
  ...
}
// 2) 把 'step 0' 换成"末步守卫 + switch 开头"
str=`if(event.step==${k}){event.finish();return;}`+str;
```

主循环（game.js:41663 起，`game.loop`）：

- 读 `var step=event.step`（41665），以此调用 `event.content(event, step, …)`（41801）；
- content 返回后 `event.step++`（41806）；
- `event.step` 无上限，**唯一出口是 content 自己调 `event.finish()`**。

#### 1.1 三条硬约束

1. **步骤号必须从 0 起连续**（0,1,2,…）。断号 ⇒ 断点后的步骤没有 `case`，
   且末步守卫按错误的 k 生成、永不成立 ⇒ `event.finish()` 永不执行
   ⇒ `event.step` 无限增长、同一段代码被反复执行 ⇒ **整个游戏循环卡死**。
2. **`'step N'` 必须写在 `content` 函数体的顶层**，绝不能嵌在 `if/else/for` 块内部。
   替换动作是 `'step N'` → `break;case N:`（game.js:12115）；若原位置在块内，
   替换后 `break`/`case` 落在块里 ⇒ 生成代码语法非法 ⇒ 该处替换被**跳过**
   （`Legacy` 用 `new Function(copy)` 试编译，失败就 continue）⇒ 步骤机错位。
   机械判据：`content` 函数体顶层缩进是 **8 个 tab**，`'step N'` 出现在 >8 tab 即违规
   （工具：`atlas/tools/audit-step-nesting.mjs`；lint 侧表现为 C1 报
   `Unexpected token 'case'`）。
   多分支的写法：**顶层判条件 + 在步骤内分派**，例如

   ```js
   'step 0'
   if (event.triggername == 'damageBegin1') { event.mzMode = 'src'; player.chooseBool(...); return; }
   event.mzMode = 'dmg';  /* 另一条分支继续 */
   player.chooseControl(...);
   return;
   'step 1'
   if (event.mzMode == 'src') { ...; event.finish(); return; }
   ...
   ```

3. **`content` 的形参只有**：`event, step, source, player, target, targets, card, cards,
   skill, forced, num, trigger, result, _status, lib, game, ui, get, ai`（game.js:12131-12133）。
   它是 `new Function` 编译的 —— **包级闭包里的局部变量在运行时看不到**。

`event.goto(n)` 语义是 `this.step = n-1`（game.js:31959-31961），
之后主循环 `++` 落到 n。`goto` 在正常建起 switch 时可用（官方 `arrangeTrigger` 就用它）；
但改步骤号时必须**同步重映射 goto 目标**（`renumber-steps.mjs --apply` 会自动做）。

### 2. 症状 → 判据速查

| 症状 | 判据 | 结论 |
|---|---|---|
| 某武将轮到他即卡死 | 插桩打印 `引擎传step` 与 `event.step`，看是否**持续增长** | 增长 ⇒ `event.finish()` 没被调用 ⇒ 先查步骤号是否连续 |
| 技能"没反应" | 在 step 0 插一条气泡，看有没有出现 | 没出现 ⇒ content 压根没执行，问题在 trigger/filter |
| 分支里某段代码像没跑 | 该分支所在步骤的编号是否在断点之后 | 断点后的步骤没被编成 case |

### 3. 诊断手段的失败史（四次，全部是我的方法错误）

| 版本 | 做法 | 失败原因 |
|---|---|---|
| ① | 把工具函数 `trace` 声明在包级闭包，content 里调用 | content 由 `new Function` 编译 ⇒ **看不到闭包变量** ⇒ 游戏报 `ReferenceError: trace is not defined` |
| ② | 改用 `C:\bz-diag.log` 写文件，失败只 `catch {}` | **静默 catch 把失败原因吞了** ⇒ 用户只看到 `ENOENT`，我拿不到任何信息 |
| ③ | 汇总行插在末步 `event.finish(); return;` **之后** | 死代码：`node --check` 能过（语法合法），运行时**永远到不了** |
| ④ | 只解析"每次修正后的行号" | 读了**过期的临时产物**（补丁是分几次加上的），据此得出的结论全无效 |

教训：

- **插桩代码只能用 content 的形参**（`game`/`player`/`event`/`lib`…），不要用闭包局部变量；
- **诊断通道的失败必须回显**，禁止 `catch {}` 里什么都不做；
- **写完插桩先确认产物的字节真的变了**（行数/关键字计数），再谈结论；
- **不可达代码不会因为语法合法而报错** —— 位置必须落在"一定会执行到的入点"
  （例如末步的**开头**，而不是末步的 `finish/return` 之后）。

### 一、收益最大的一条：**触发键 ≠ 事件名**

这一个认知错误，**独立害了三个技能**，前后白改 4~5 轮。

| 我想判的东西 | 我写的 | 实际 | 后果 |
|---|---|---|---|
| 伤害结算阶段 | `event.name == 'damageBegin2'` | `event.name` **恒为 `damage`**（阶段看 `event.step`） | 加伤从不生效 |
| 回合结束 | `event.name == 'phaseJieshuBegin'` | `event.name` 是 **`phaseJieshu`** | 破敌结算从不进入 |
| 阶段名 | `event.triggername` | filter 里常为 **`undefined`** | 分派恒假 |

**正确写法**：

```js
// ✓ 伤害：直接用触发键；只挂一个（挂多个会重复叠加，实测 num 从 1 涨到 46）
trigger: { source: 'damageBegin4' },          // step 4 = 最终结算前最后一步
content: function () { trigger.num++; }

// ✓ 阶段：比 event.name（不带 Begin）
filter: (e) => e.name == 'phaseJieshu'

// ✓ 判定手段：打印 event.name + event.step（本轮就是靠这个定死的）
```

**教训**：凡是"按名字分派"的地方，先怀疑名字本身。

### 二、让我连错四次的：**dialog / 选牌 API**

同一个需求（让玩家从一组牌里选一张）我换了 5 种写法，只有最后一种对：

| 写法 | 结果 |
|---|---|
| `chooseCardButton(裸牌数组)` | 崩：`Cannot read properties of undefined (reading '1')` |
| `chooseButton(['…', [list, 'card']], true)` | 崩：`item.cloneNode is not a function` |
| `chooseButton(['…', [list, 'vcard']], true)` + `get.cardsInfo()` | 崩：`Cannot read properties of undefined (reading 'name')` |
| `chooseButton(['…', [list, 'vcard']], true)` 传裸牌 | **显示成"牌名"而不是卡牌** |
| **`chooseCardButton(cards, prompt)`** | ✅ 正确（`game.js:24886`，内部 `[prompt,cards,'hidden']`） |

**要点**：
- `'vcard'` 的 list 必须是 **`[type, suit, name]` 数组**（`dy_wuku` 就那样用）—— 传实体牌就会渲染成牌名
- 选**实体牌**用 `chooseCardButton`；选**虚拟牌名**用 `chooseButton + 'vcard'`
- `forced` **只在显式传 boolean 时**才设置 ⇒ 想"可以取消"就别传 `true`

**教训**：**别自己拼 dialog 结构** —— 找引擎里同名能力的专用 API。

### 三、机制类坑（各害 1~2 轮）

#### 3.1 一个技能不能同时做"主动发动"和"时机触发"

```js
// ✗ 引擎视作同一技能 ⇒ 时机到来时走"主动发动"那条 content
gy_po_di: { enable: 'phaseUse', trigger: { player: 'phaseJieshuBegin' }, content: … }
// 实测症状：**回合结束自动触发了这个技能**（弹出选目标对话框），结算分支从不执行
// ✓ 拆成两个技能：一个只 enable，一个只 trigger
```

#### 3.2 `'s'` 区 = "放在**手牌容器**里的牌"

`loseToSpecial` 最终走 `directgains`（`game.js:25965-25993`）：

```js
cards[i].classList.add('glows');
node.appendChild(cards[i]);       // → this.node.handcards1  ← 手牌容器
```

⇒ 牌**显示在手牌区、并被引擎当可用牌**（用户实测"武将牌上的牌能直接点用"）。
想要"看得见但不能直接用" ⇒ `addToExpansion`（进 `player.node.expansions` 独立容器）。

#### 3.3 mod 必须挂在"技能确实在身上"的技能上

把 `mod.cardUsable` 挂在子技能上、而那个子技能**不在武将数组里** ⇒ 技能不在身上 ⇒ **mod 永不生效**（"杀不计入次数限制"失效的真因）。
⇒ 关键 mod 一律并进**始终存在的主技能**。

#### 3.4 无效化：照抄原版「看破」

```js
// ✗ 我自己编的字段（引擎里没有）
trigger.cancelled = true; trigger.triggered.zl_kongcheng = true;
// ✓ 原版 sb.js:3087-3091 谋诸葛亮「看破」
trigger.targets.length = 0;
trigger.all_excluded = true;
```

#### 3.5 事件字段别靠猜

| 事件 | 关键字段 | 坑 |
|---|---|---|
| `useCardToTargeted` | `event.targets`（全量）/ `event.target`（本次） | 是**逐目标**派发：多目标牌为每个目标各派发一次（含使用者自己）。**必须自己判"我是不是目标"**，否则"对别人出牌也触发空城" |
| `dieAfter` | `event.source` | 击杀者判定用它，不是 `event.player` |
| 伤害事件 | `event.num` | 改 `trigger.num` 有效，但**阶段要对**（见 §1） |

#### 3.6 共用子技能的 id 列表会过期

`tdgx_shenwei_kill` 里维护着"哪些技能算神威技"的 id 列表。删掉/重写武将会让列表失效（本次列表里全是**已删除武将**的旧 id，且**新神威技没进列表**）⇒ 击杀后次数永不 +1。
⇒ **任何"按 id 列举"的地方，删改武将后必须同步**。

### 四、方法论的坑（比引擎坑更贵）

#### 4.1 诊断必须**双通道**

- 只写文件 ⇒ 用户看不到
- 只写战报 ⇒ **作者读不到**（战报不落盘）
- ⇒ `game.log(...)` **和** `require('fs').appendFileSync(...)` **同时写**

并且：**`content`/`filter` 由 `new Function` 编译，严格模式下 `require` 不是自由变量** ⇒ 写文件要走挂在 `game` 上的 helper（`game.lib.bzDiag2`）。
另外诊断**失败必须可见** —— 曾用 `catch {}` 吞掉写入异常，误判"通道不通"，白跑多轮。

#### 4.2 "游戏没完全重启"会吃掉所有诊断

反复出现的现象：我部署了带诊断的版本 → 用户测 → 日志为空。
根因是**游戏进程未重启，加载的仍是旧代码**，而我又在部署时清空了日志。
⇒ 测前**先看日志里有没有开机自检那一行**（一行 `【开机自检】版本=…` 就能确认版本已加载）。

#### 4.3 用户说"好了"可能是"我测完了"

我三次把"好了"读成"修好了"，导致结论错、方向偏。
⇒ 一律按**"我去看数据"**处理，需要结论就明说"这次是修好了还是测完了"。

#### 4.4 先拿数据，再改代码

本轮最有效的一步是**"无条件诊断"**：把日志放在 filter **最前面**（任何 return 之前），不看条件、不做判断 —— 一次就分清"filter 没被调用"和"条件不满足"。
相对地，我前期"改一版 → 用户测 → 再猜"的循环，效率极低且反复误判。

#### 4.5 有原版同类实现时，照抄而不是自创

本轮用户三次提示"看某诸葛亮的代码"，每次都直接解决问题：

| 需求 | 原版参考 | 我自创的错法 |
|---|---|---|
| 武将牌上的牌区 | 谋诸葛亮「观星」`sbguanxing` | 自制 storage 存牌引用（牌没进区域） |
| 令牌无效 | 谋诸葛亮「看破」`sbkanpo` | `trigger.cancelled`（自造字段） |
| 伤害+1 | 原版 43 处 `damageBegin2` | 按 `event.name` 分派（恒假） |
| 选实体牌 | `chooseCardButton` | 手拼 `[list,'vcard']` 等 4 种错法 |

⇒ **动手前先 grep 一个同类技能，照它的骨架写**；实在没有先例时，再标注"无先例，自创"。

### 五、台词（audio）配置备忘

- 语音文件：`resources/app/audio/skill/<key><n>.mp3`；技能上写 `audio: '<key>'`，引擎按 `<key>1/2/3…` 随机播放

### 一、背景

本小姐想给自己 DIY 一个三国杀武将 **谋郭嘉·魂**（三技能：定策 / 铸策 / 沥血），
用 lycium 在线制卡器 2.5.4 制卡定稿，然后落地到无名杀框架的客户端游戏里。

**武将设定（卡面原文）**：

| 技能 | 类型 | 效果 |
|---|---|---|
| 定策 | 锁定技 | 游戏开始时选择一名其他角色获得「策」，你与该角色相互间无法造成伤害；你死亡时可选择移除「策」 |
| 铸策 | — | 你的回合开始时，给「策」添加一项效果：①回复体力 ②额外执行一个出牌阶段（**不摸牌**）③使用牌造成的伤害+1（单目标）④跳过弃牌阶段（前三项各限一次并永久） |
| 沥血 | 锁定技 | 你体力值发生变动时，与「策」各摸 X+1 张牌（X 为「策」已有效果数） |

**核心难点不是写技能，而是搞懂这个框架的「包」是怎么被加载、注册、触发的。**
期间经历了两次惨烈翻车（游戏直接崩溃、包名 undefined），第三次才修成正果。
本文把成功路径 **和** 引擎源码级的原因分析全部记录下来。

### 二、踩坑时间线（血泪史）

#### ❌ 第 1 次：把包直接扔进 `resources\app\character\`

照网上老教程在 `character\` 目录新建 `myguojia.js`，写 `game.import('character', ...)`。

**结果：游戏启动直接崩溃，进不去了。**

排查：这个目录是**内置角色包目录**，启动时被固定列表扫描加载（`config.js` 的 `characters` 白名单），
自定义文件混进去会破坏加载时序——**此路不通**。文件改名 `.disabled` 才救回游戏。

> ⚠️ 改坏了不用担心：琉璃版的加载器只认 `.js` 后缀，`xxx.js.disabled` 会被安全忽略。

#### ❌ 第 2 次：`lib.characterPack` 直塞 + `translation`（复数）

改成在 `extension\` 里建扩展，启用时往 `lib.characterPack['myguojia']` 塞数据，
`lib.skill` / `lib.translate` 手动注册，翻译块写成 `translation: {...}`（复数）。

**结果：扩展能出现在列表里，但 包名是 undefined、选将列表里选不了这个角色。**

原因（源码级）：
1. `lib.characterPack` 直塞**绕过了引擎的注册链**——引擎维护自己的导入队列，
   直接塞进去的角色不会被 `lib.skilllist`、`lib.character` 展平、选将 UI 索引所承认。
2. 这版引擎读的是 **`translate`（单数）**，`translation` 是另一个版本的 API，完全不生效。
3. 扩展壳里 `game.import('character')` **不在正确时机**执行——角色包必须走
   `lib.imported.character` → 游戏开局注册链，而不是直接改对象。

#### ✅ 第 3 次（成功）：完全照抄「雷霆万钧」官方扩展的姿势

参考 `extension\雷霆万钧\extension.js`（游戏自带的官方扩展），
发现真正的标准姿势只有一句话：

> **扩展壳的 `precontent` 里调用 `game.import('character', fn)`，返回的对象带
> `name / character / translate / skill`（加中文翻译块），完事。**

**这就是全部。** 之前两次翻车都是因为没走这条唯一正路。

### 三、正确的标准格式（可直接抄）

```js
// 扩展文件结构
game.import('extension', function (lib, game, ui, get, ai, _status) {
	return {
		name: '天地归一',          // 扩展显示名
		editable: false,
		precontent: function () {   // ← 启用扩展时立刻执行（雷霆万钧同款）
			game.import('character', function () {
				// 闭包内可写辅助函数（不会污染全局！）
				var findCeTarget = function () { /* ... */ };

				return {
					name: 'tiandiguiyi',  // ★ 包名（内部 ID）
					character: {           // ★ 武将（数组式）
						mouguojia_soul: ['male', 'wei', 4, ['mgj_dingce', 'mgj_zhuce', 'mgj_lixue', ...]],
					},
					characterIntro: { mouguojia_soul: '……' },
					translate: {           // ★ 单数！包名 key = 包 name
						'tiandiguiyi': '天地归一',
						'mouguojia_soul': '谋郭嘉·魂',
						'mgj_dingce': '定策',
						'mgj_dingce_info': '锁定技。……',
					},
					skill: {               // ★ 技能全放在这里
						mgj_dingce: { forced: true, trigger: {...}, content: function(){ 'step 0' ... } },
						// ...
					},
				};
			});
		},
	};
});
```

**再装进游戏**：
1. `config.js` 的 `extensions: [...]` 数组末尾追加你的扩展名（游戏启动才会扫描到）
2. 重启游戏 → 扩展管理 → 启用
3. **开一局新游戏**（角色包在开局时注册）
4. 选将界面 → 武将包包名 → 你的武将

> 技巧：`game.import('character')` 放在 `precontent`（启用即导入）而不是 `content`（开局才执行），
> 这样任何时机启用扩展，包都会在下一局游戏开始时被注册。
> 如果放在 `content` 里，包注册链的调用时机也可行，但 precontent 是雷霆万钧验证过的姿势。

### 四、引擎机制研究（源码级，这是本心得最值钱的部分）

以下全部对照琉璃版 5.5 `game/game.js` 源码，行号可直接复查。

#### 4.1 两条 import 通道

```js
game.import('extension', obj)     // → game.loadExtension(obj)：立即加载扩展
game.import('character', fn)      // → 收集进 lib.imported.character[name]
```

- `extension` 通道：执行扩展对象，注册 `lib.extensionMenu` 等（game.js 37520+）
- 其他类型（character/card/mode）：**只是收进 `lib.imported[type]`**，由 **游戏开始/重开时的注册链** 统一处理（game.js 15126+）

**结论：自定义武将包不要直接动 `lib.characterPack`，要走导入队列。**

#### 4.2 角色包注册链（游戏开局时，game.js L15126）

对 `lib.imported.character` 的每个包：

```
character[i].character → lib.characterPack[i]          （按包名入包）
character[i].skill     → lib.skill[k]（defineProperty 注册）
character[i].translate → lib.translate[k]
角色数组[3] 的技能     → lib.skilllist（选将界面技能索引）
```

随后（L35486）：`lib.characterPack` 全部展平进 `lib.character`（`lib.character[j] = lib.characterPack[i][j]`），
至此选将 UI 才能看到你的武将。

> ⚠️ **重点（第 2 次翻车实测验证过的坑）**：L11224 启动链里有个 `lib.config.characters` 白名单
> （config.js 的 `characters:[...]`，即「已启用武将包」列表）。
> 包在链中**先注册** `lib.characterPack` 和 translate（所以**包标签/包名能显示**），
> 但 `j=='character'` 这一支若**包名不在 `lib.config.characters` 里会被直接 continue 跳过**——
> **武将不进 `lib.character`、技能不进 `lib.skilllist`** → **选将界面出现「有标签、没武将」的空包**！
>
> **正解（雷霆万钧 L8959-8962 同款「包名注册三连」，扩展自己搞定）**：
>
> ```js
> lib.config.all.characters.push('tiandiguiyi');                          // ① 候选列表
> if (!lib.config.characters.contains('tiandiguiyi'))                     // ② 启用列表（白名单通过）
>     lib.config.characters.add('tiandiguiyi');
> lib.translate['tiandiguiyi_character_config'] = '天地归一';              // ③ 包名标签（UI 读这个 key）
> ```
>
> 三个缺一不可：①没有 → 包不出现；②没有 → 空包；③没有 → 标签显示 "undefined"。
> 另外 `game.js` 里有三处 `lib.characterPack → lib.character` 展平（L35486 在线分支 / L38094 回放），
> 保险起见可在导入后**手动幂等展平**（本仓库代码已这样做）。

##### 4.2.1 展平不是自动的（2026-09-10 源码复核）

**`game.import(type, content)` 对非 extension 类型只做一件事**：

```js
// game.js:37529-37534
const promise = Promise.resolve((...)(lib,game,ui,get,ai,_status)).then(content2 => {
    if (content2.name) {
        lib.imported[type][content2.name] = content2;
        delete content2.name;
    }
});
```

它**不碰** `lib.character` / `lib.skill` / `lib.translate`。真正写入 `lib.*` 的是启动期的
**一次性**循环（`game.js:15126-15181`）：

```
character[i].character      → lib.character[k]（并给 [4] 补空数组、收拢 skilllist）
character[i].skill          → lib.skill[k]
character[i].translate      → lib.translate[k]
character[i].characterIntro → lib.characterIntro[k]
```

而 `lib.imported.character` 在 `game.js:11541` 就被 `delete` 掉了，扩展加载循环
（`game.js:11550` 起）又在它**之后** —— 所以 `precontent` 里 import 的包
**不保证**被这趟循环扫到。踩坑表现就是「技能能发动、但武将名/包名是空的」。

**结论：扩展必须自己再展平一遍**（幂等，`== undefined` 守卫，两种时序结果一致）：

```js
if (pkg) {
    if (pkg.skill) for (var sk in pkg.skill)
        if (lib.skill[sk] == undefined) lib.skill[sk] = pkg.skill[sk];
    if (pkg.translate) for (var tk in pkg.translate)          // ★ 武将名能不能显示就靠这条
        if (lib.translate[tk] == undefined) lib.translate[tk] = pkg.translate[tk];
    if (pkg.characterIntro) for (var ik in pkg.characterIntro)
        if (lib.characterIntro[ik] == undefined) lib.characterIntro[ik] = pkg.characterIntro[ik];
    if (pkg.character) for (var cid in pkg.character) {
        if (!lib.character[cid]) lib.character[cid] = pkg.character[cid];
        if (!lib.character[cid][4]) lib.character[cid][4] = [];   // 15146-15148 同款
        var skl = lib.character[cid][3];
        for (var si = 0; si < skl.length; si++)
            if (!lib.skilllist.contains(skl[si])) lib.skilllist.add(skl[si]);
    }
}
```

**武将名为什么不显示，链路一次说清**：`game.js:22838` 无条件执行
`this.node.name.innerHTML = get.slimName(character)`；`get.slimName`（`game.js:61648-61651`）
第一件事就是 `var str2 = lib.translate[str]`，`if(!str2) return ''` —— **取不到译名就返回空串**，
名字位因此空白（不是报错、不是样式问题）。

**附带一条必须知道的引擎怪癖**（`game.js:15160-15162`）：

```js
if (j == 'translate' && k == i) {                          // k = translate 的键，i = 包名
    lib[j][k + '_character_config'] = character[i][j][k];  // ← 键 == 包名 → 改道！
}
else { /* ...正常写入 lib[j][k]... */ }
```

即当 `translate` 的键**恰好等于包名**时，引擎**不会**写 `lib.translate[包名]`，
而是改写成 `lib.translate[包名 + '_character_config']`。选将界面的包名标签读的正是后者，
所以「包名标签显示 undefined」要补的是 `_character_config` 这一条，而不是包名本身。

#### 4.3 技能必须出现在玩家的技能列表里，才会被触发（最关键的坑！）

事件触发链（game.js）：

```
game.trigger(event)                       L32310
  → 从 lib.hook 桶取技能（addSkillTrigger L27805 注册：playerid_player_事件 → [技能名]）
  → arrangeTrigger 过滤（L15276 filter1）
    → filterTrigger（L33031）
      → player.getSkills(false).contains(skill)   ← L33042~33044！
```

**L33044 的 `!fullskills.contains(skill)` 判定**：触发前检查该技能名必须在
`player.getSkills(false)`（= `player.skills` + `invisibleSkills` + 装备技能）里，
否则**直接跳过**。

这解释了第 2 次翻车「选了角色但技能全不发动」的潜在机制，也解释了本心得的一个**重要设计决策**：

> **即使是隐藏子技能，也必须列进武将的技能数组**（`character:[..., ['mgj_dingce', 'mgj_nohurt', ...]]`），
> 开局 `addSkill` 逐个挂到玩家身上后才会被事件系统认领（`lib.character[3]` 循环 addSkill，见 L23092）。

隐藏方式：子技能对象加 `sub: true` + `popup: false` + `charlotte: true`（或用 `silent: true` 自动补全），
选将界面技能栏（`getStockSkills` L24007）会过滤掉 `sub`/`charlotte` 技能，不显示但功能正常。

#### 4.4 trigger 写法与双键

```js
trigger: { player: 'phaseBegin' }            // 标准单键
trigger: { global: 'damageBegin' }           // 所有玩家监听
trigger: { global: 'gameStart', player: 'enterGame' }   // ★ 官方双键（L34301 同款）
trigger: { player: ['damageEnd', 'recover'] }  // 事件数组
```

解析逻辑（L33054）：`for (var i in info.trigger) if ((i == 'global' || player == event[i]) && has(...))`——
键为 `global` 时对所有玩家匹配；其他键按 `event[键] == player` 匹配。**双键/数组完全合法**。

定策用了 `{ global: 'gameStart', player: 'enterGame' }`：开局靠 `gameStart`（每个玩家 filter 一次），
复活/换将靠 `enterGame` 兜底，重复触发用自加标记 `mgj_ce_bound` 防重。

#### 4.5 subSkill 的自动注册（以及为什么我弃用了它）

`game.finishSkill`（L44094）里有：`if (info.subSkill) Object.keys(...).forEach` 把
`子技能名 = 父名_子名` 注册进 `lib.skill`（L44153），并处理子技能翻译/优先级。

**但这只在 `finishCards()`（L44283，游戏启动遍历全部技能）时跑**。扩展包如果是
开局之后才导入，主技能**可能没被 finishSkill 处理过** → 子技能没被注册 →
`addSkill` 时 `lib.skill[子技能名]` 不存在 → 直接 return（L28177-28178 静默失败）。

**所以最稳方案**：不依赖 subSkill 自动注册，把子技能直接写成**顶层技能**（名字独立），
每个加 `sub: true` 隐藏显示。反正技能都列进角色数组，触发机制完全一致。
（`subSkill` 嵌套本身在官方角色里很多，若你导入时机在游戏启动链之前，也完全可用；
选择权在你。）

#### 4.6 额外执行一个出牌阶段（不摸牌）的正确姿势

> ⚠️ **勘误（2026-09-10 源码复核，同日二次修正）**：本条原写
> `trigger.getParent().next.unshift(next)`，说「插到当前流程最前面」。
>
> **第一次复核**（只读了 sb.js / jsrg.js 两处）我断言「17 处全部是
> `trigger.next.push`，没有一处用 `getParent()`」—— **这个断言是错的，是抽样代替普查。**
> 后来用 [`atlas/tools/idiom.mjs`](atlas/tools/idiom.mjs) 做全库聚类才拿到真实分布：
>
> | 写法 | 处数 |
> |---|---|
> | `event.next.remove` → `trigger.next.push` | **8** |
> | `event.next.remove` → `trigger.getParent()` → `next.push` / `next.unshift` | **7** |
> | 其他机制（`insertPhase` / 直接 `phaseUse`） | 2 |
>
> 全库命中 17 个技能，**8 : 7 —— 不存在压倒性写法**。
> 教训：**语料是证据不是判决，而且要普查、不要抽样。**

现有两个流派，判据在引擎主循环（`game.js` 41700 附近）：`event.next` 队列是在
**当前事件每一步之间**被消费的。`trigger` 是**触发事件自身**（`game.js:41675`
`trigger=event._trigger`；`{player:'phaseBegin'}` 的触发事件就是 `phaseLoop`），
所以挂到 `trigger.next` 会落在 `phaseLoop` 的 step 7（触发 phaseBegin）与
step 8（建立 `phaseList` 各阶段，`game.js:15965-15968`）**之间** —— 正是「紧接着回合开始」。
挂到 `trigger.getParent().next` 则是父事件的队列，要等 `phaseLoop` 整体跑完才轮到，
即排到**整个回合之后**。

```js
var next = player.phaseUse();     // ① 创建（此刻挂在当前事件 _status.event.next 末尾）
event.next.remove(next);          // ② 从末尾摘掉
trigger.next.push(next);          // ③ 挂到触发事件自身的 next → 步与步之间即执行
```

可交叉验证的先例：

| 位置 | 技能 | 卡面 |
|---|---|---|
| `sb.js:3951` | 琉璃 | — |
| `jsrg.js:317` | 离叛 | 额外出牌阶段 |
| `yijiang.js:7399` | 当先 | 「回合开始时，执行一个额外的出牌阶段」← **与铸策②逐字同义** |
| `mobile.js:11691` / `diy.js:6516` / `sp.js:3804` … | — | 同派共 8 处 |
| `clan.js:2176` / `refresh.js:5700` / `xianding.js:8284` … | — | `getParent()` 派共 7 处 |

- `trigger.next` 是**触发事件自身**的后续队列。`phaseBegin` 在 `phaseLoop` 的 `'step 7'`
  触发（`game.js:15953-15956`），而阶段序列要到 `'step 8'` 才创建
  （`game.js:15965-15968` `player[event.currentPhase]()`）→ 挂在这里的 `phaseUse`
  正好落在「回合开始之后、正常阶段之前」，即卡面要的「额外」出牌阶段。
- 反过来，`trigger.getParent()` 拿到的是 `phaseLoop`，它的 `next` 队列是**整个回合跑完后**
  才消费的 → 原写法会把出牌阶段排到结束阶段之后。
- `phaseUse` 本身不含摸牌（摸牌是 `phaseDraw` 的事），天然满足「不摸牌」。

顺带一个必须记住的时机结论：**`phaseBegin` = 回合开始，每回合只发一次**（不是每阶段一次）。
判据就在 `game.js:15950-15968`：注释「回合开始后⑨」的 `'step 7'` 触发 `phaseBegin`，
之后 `'step 8'` 才建立 `phaseList` 的各阶段。所以拿 `{global:'phaseBegin'}` 做「你的回合开始时」
是安全的，永久化也不会变成「每阶段触发一次」。

#### 4.7 锁定技 + 需要选择的内容

`forced: true` 只是「不弹发动按钮直接进 content」，**content 里照样可以弹
`chooseTarget` / `chooseBool`**（官方大量锁定技都是 forced + 内部选择），写起来没负担。

#### 4.8 体力变动

沥血用 `trigger: { player: ['damageEnd', 'recover', 'loseHpEnd'] }` 覆盖掉血/回血/失去体力
—— **`loseHp` 是独立事件**（`game.js:26455 createEvent('loseHp')`），不产生 `damage` 事件，
只挂 `damageEnd` 会漏掉「失去体力」，与卡面「体力值发生变动」不符。
伤害数值的修改则用 `{global:'damageBegin'}` + 比对 `event.source` + `event.card` 判断单目标
（`get.info(event.card).selectTarget == 1` 排除南蛮/万箭等 AOE）。**改数值要改 `trigger.num`
（`game.js:41674` 伤害值就是 `event.num`），`event.damage` 在引擎里出现 0 次、改了等于没改。**

### 五、成品技能实现要点（`extension.js`）

- `mgj_dingce`（定策）：`forced + {global:['gameStart','gameDrawAfter'], player:'enterGame'}`，
  content 内 `chooseTarget` 选「策」目标，`mgj_ce_bound` 防重复；
  子技能 `mgj_nohurt`（damageBegin 相互免伤，`trigger.cancel()`）、
  `mgj_ce_remove`（die 时 chooseBool 移除）。
  > 触发时机为什么放宽成三个：`enterGame` 只在 `addFellow` / `restorePlayer` 里由
  > `game.triggerEnter` 创建（`game.js:44881`），**正常开局不会触发**；
  > `gameStart` 由各模式自己派发（如 `mode/identity.js:355`），时机受模式影响不保证；
  > 因此补 `gameDrawAfter` 兜底，三者谁先到就用谁（`ceBound` 保证只落一次）。
- `mgj_ce_bound` 为什么用 `player.storage.mgj_ce_bound` 而不是裸标记：裸标记取不到
  `lib.skill[...].intro`，`markSkill` 会直接 return（`game.js:27412-27417`）——
  纯记账状态放 `storage` 更干净（`mgj_picked1/2/3` 则故意用裸标记，正好借这个特性隐藏）。
- `mgj_zhuce`（铸策）：`{player:'phaseBegin'}`。**每回合四选一**，不是四连发 ——
  content 里先按 `mgj_picked1/2/3` 组装「当前还能添加」的选项，
  再用 `chooseControl(labels)` 弹一次选择，然后只 addMark 选中的那一项；

- `mgj_lixue`（沥血）：`forced + {player:['damageEnd','recover']}`，
  X = 四枚效果标记之和，`player.draw(X+1,'nodelay')`，双方都摸。

### 3. 四处既有缺陷（**不是本次改动引入的**）

判定依据：把 `parsex`（`game.js:12094-12133` 的 Legacy 分支）**逐字抄进脚本**，对新旧两版编译并打印
生成的 `switch/case` 结构 —— 两版**逐字相同** ⇒ 这些都是老代码自带的。

#### 3.1 `drawN` 未定义

草稿第 4672 行 `get.cnNumber(drawN)`，而 `drawN` 全文件**只此一次出现** ⇒ ReferenceError。

#### 3.2 B1 —— filter 的 `return false` 吞掉了"使用【杀】"

```js
filter: function (event, player, name) {
    if (event.name == 'useCard' && event.player == player) {
        …找马牌…
        return false;                  // ← 元凶
    }
    // 下面这段"使用或打出【杀】"的判定 永远够不到
}
```

【杀】走的也是 `useCard` ⇒ 命中这个分支后**直接 `return false`**，下面那段判定是死代码。
症状：**只有"打出【杀】"能触发雷击，"使用【杀】"不能**。由提交 `875ea7a` 引入。

#### 3.3 B2 —— 两个 `'step 1'`，`case 1:` 编到了另一条分支

`content` 里有两个 `'step 1'`：一个 **9 tab 嵌在 `if` 里**，一个 **8 tab 顶层**。

引擎的兜底逻辑是（**实读** `game.js:12106-12128`）：

```js
catch (error) { k--; skip += result.index + result[0].length; }
```

即**跳过这一处、用同一个编号继续找下一处同名标记** —— 不是"整段作废"。
嵌套那个（`case` 出现在 `switch` 内嵌块里，V8 直接拒绝）被跳过，
于是 **`case 1:` 落到了顶层那个（【杀】分支）**。

后果：玩家答完获马对话框后，执行的是**另一条分支**的代码，读到 `result.control`
（没有 `.bool` 属性）就 `event.finish()` ⇒ **三个选项永不生效**。

#### 3.4 B3 —— 装备坐骑弹两次对话框

装备坐骑时引擎同时派发 `equip` 与 `useCard` 两个事件 ⇒ 对话框回弹两次。

### 5. 语音改造

#### 5.1 为什么原先完全没声音

旧写法是 `audio: 'shen_machao'` —— **那是"角色 id"，不是"技能名"**。
引擎解析链（`game.js:37382` 起）在字符串既不是技能名、又不以 `ext:` 开头时，
走到 `37401` 直接 `return` ⇒ **静默无声**。

正确写法是**指向真实技能名**：神马超的官方范式就是 `psshouli:{audio:'shouli'}`、
`pshengwu:{audio:'hengwu'}`；素材在 `audio/skill/shouli1-2.mp3`、`hengwu1-2.mp3`。

> 顺带排除一个诱饵：`audio/skill/shoulijian.mp3` **不是**神马超的 ——
> `card/huanlekapai.js:36` 里 `shoulijian` 是欢乐卡牌「手里剑」。

#### 5.2 为什么只有主动技出声

`mx_shenwei` / `mx_yulei` 都是 `direct: true`，而引擎 `game.js:37361`
`if(info.direct&&!directaudio) return;` —— **direct 技能的自动播放到这里就被跳过了**。

修法：在两者**真正生效**的分支里自己调 `game.trySkillAudio('<技能名>', player, true)`
（第三参 `true` = directaudio），共 **6 处落点**：

- `mx_shenwei`：获马三选一**选到选项时**（选「放弃」不出声）、雷击结算完
- `mx_yulei`：免雷（`damageBegin2`）/ 造成雷伤（`damageSource`）/ 新回合（`phaseBefore`）/ 回合末充能（`phaseEnd`）

每个落点都逐个对着分支核过，**不是**把调用堆在函数开头。

> 附带好处：扩展自身已挂钩 `game.trySkillAudio` 做诊断（内部 `return _origTrySkillAudio.apply(game,arguments)`，
> 不影响行为），所以每次播放都会在 `C:/bz-diag.log` 留一行 `【语音】…`，便于核对落点是否真的执行到。

### 8. 本次新增、已回填到硬规则清单的引擎事实

1. **`direct:true` 的技能引擎不播音频**（`game.js:37361`）→ 必须自己 `trySkillAudio(…, true)`。
2. **完整 audio 解析链**（`37371-37417`），含 `info.audioname` 后缀机制与 `ext:` 形式。
3. **数组形态的 `audio` 有 TypeError 风险**：`37390` 对 `lib.skill[audioinfo[0]]` **没有判空**。
4. **扩展角色的 audioname 后缀陷阱**：`37396` 拼的是 `player.name`（扩展角色是 `tdgx_xxx`），
   照抄游戏写法会拼出不存在的文件名。
5. **`'step N'` 校验失败的真实语义**是「跳过该处、以同一编号继续找下一处」（B2 的根因）。
6. **generator 检测在 parsex 的分派处**（`game.js:12163-12180`），不在 Legacy 分支里。
7. **`filter` 的第三参数 `name` 确实存在**（`game.js:33031` / `33060`），值就是当前命中的触发键名。
