## 一、背景

本小姐想给自己 DIY 一个三国杀武将 **谋郭嘉·魂**（三技能：定策 / 铸策 / 沥血），
用 lycium 在线制卡器 2.5.4 制卡定稿，然后落地到无名杀框架的客户端游戏里。

**武将设定（卡面原文）**：

| 技能 | 类型 | 效果 |
|---|---|---|
| 定策 | 锁定技 | 游戏开始时选择一名其他角色获得「策」，你与该角色相互间无法造成伤害；你死亡时可选择移除「策」 |
| 铸策 | — | 你的回合开始时，给「策」添加一项效果：①回复体力 ②额外执行一个出牌阶段（**不摸牌**）③使用牌造成的伤害+1（单目标）④跳过弃牌阶段（前三项各限一次并永久） |
| 沥血 | 锁定技 | 你体力值发生变动时，与「策」各摸 X+1 张牌（X 为「策」已有效果数） |

**核心难点不是写技能，而是搞懂这个框架的「包」是怎么被加载、注册、触发的。**
期间经历了两次惨烈翻车（游戏直接崩溃、包名 undefined），第三次才修成正果。
本文把成功路径 **和** 引擎源码级的原因分析全部记录下来。

## 二、踩坑时间线（血泪史）

### ❌ 第 1 次：把包直接扔进 `resources\app\character\`

照网上老教程在 `character\` 目录新建 `myguojia.js`，写 `game.import('character', ...)`。

**结果：游戏启动直接崩溃，进不去了。**

排查：这个目录是**内置角色包目录**，启动时被固定列表扫描加载（`config.js` 的 `characters` 白名单），
自定义文件混进去会破坏加载时序——**此路不通**。文件改名 `.disabled` 才救回游戏。

> ⚠️ 改坏了不用担心：琉璃版的加载器只认 `.js` 后缀，`xxx.js.disabled` 会被安全忽略。

### ❌ 第 2 次：`lib.characterPack` 直塞 + `translation`（复数）

改成在 `extension\` 里建扩展，启用时往 `lib.characterPack['myguojia']` 塞数据，
`lib.skill` / `lib.translate` 手动注册，翻译块写成 `translation: {...}`（复数）。

**结果：扩展能出现在列表里，但 包名是 undefined、选将列表里选不了这个角色。**

原因（源码级）：
1. `lib.characterPack` 直塞**绕过了引擎的注册链**——引擎维护自己的导入队列，
   直接塞进去的角色不会被 `lib.skilllist`、`lib.character` 展平、选将 UI 索引所承认。
2. 这版引擎读的是 **`translate`（单数）**，`translation` 是另一个版本的 API，完全不生效。
3. 扩展壳里 `game.import('character')` **不在正确时机**执行——角色包必须走
   `lib.imported.character` → 游戏开局注册链，而不是直接改对象。

### ✅ 第 3 次（成功）：完全照抄「雷霆万钧」官方扩展的姿势

参考 `extension\雷霆万钧\extension.js`（游戏自带的官方扩展），
发现真正的标准姿势只有一句话：

> **扩展壳的 `precontent` 里调用 `game.import('character', fn)`，返回的对象带
> `name / character / translate / skill`（加中文翻译块），完事。**

**这就是全部。** 之前两次翻车都是因为没走这条唯一正路。

## 三、正确的标准格式（可直接抄）

```js
// 扩展文件结构
game.import('extension', function (lib, game, ui, get, ai, _status) {
	return {
		name: '天地归一',          // 扩展显示名
		editable: false,
		precontent: function () {   // ← 启用扩展时立刻执行（雷霆万钧同款）
			game.import('character', function () {
				// 闭包内可写辅助函数（不会污染全局！）
				var findCeTarget = function () { /* ... */ };

				return {
					name: 'tiandiguiyi',  // ★ 包名（内部 ID）
					character: {           // ★ 武将（数组式）
						mouguojia_soul: ['male', 'wei', 4, ['mgj_dingce', 'mgj_zhuce', 'mgj_lixue', ...]],
					},
					characterIntro: { mouguojia_soul: '……' },
					translate: {           // ★ 单数！包名 key = 包 name
						'tiandiguiyi': '天地归一',
						'mouguojia_soul': '谋郭嘉·魂',
						'mgj_dingce': '定策',
						'mgj_dingce_info': '锁定技。……',
					},
					skill: {               // ★ 技能全放在这里
						mgj_dingce: { forced: true, trigger: {...}, content: function(){ 'step 0' ... } },
						// ...
					},
				};
			});
		},
	};
});
```

**再装进游戏**：
1. `config.js` 的 `extensions: [...]` 数组末尾追加你的扩展名（游戏启动才会扫描到）
2. 重启游戏 → 扩展管理 → 启用
3. **开一局新游戏**（角色包在开局时注册）
4. 选将界面 → 武将包包名 → 你的武将

> 技巧：`game.import('character')` 放在 `precontent`（启用即导入）而不是 `content`（开局才执行），
> 这样任何时机启用扩展，包都会在下一局游戏开始时被注册。
> 如果放在 `content` 里，包注册链的调用时机也可行，但 precontent 是雷霆万钧验证过的姿势。

## 四、引擎机制研究（源码级，这是本心得最值钱的部分）

以下全部对照琉璃版 5.5 `game/game.js` 源码，行号可直接复查。

### 4.1 两条 import 通道

```js
game.import('extension', obj)     // → game.loadExtension(obj)：立即加载扩展
game.import('character', fn)      // → 收集进 lib.imported.character[name]
```

- `extension` 通道：执行扩展对象，注册 `lib.extensionMenu` 等（game.js 37520+）
- 其他类型（character/card/mode）：**只是收进 `lib.imported[type]`**，由 **游戏开始/重开时的注册链** 统一处理（game.js 15126+）

**结论：自定义武将包不要直接动 `lib.characterPack`，要走导入队列。**

### 4.2 角色包注册链（游戏开局时，game.js L15126）

对 `lib.imported.character` 的每个包：

```
character[i].character → lib.characterPack[i]          （按包名入包）
character[i].skill     → lib.skill[k]（defineProperty 注册）
character[i].translate → lib.translate[k]
角色数组[3] 的技能     → lib.skilllist（选将界面技能索引）
```

随后（L35486）：`lib.characterPack` 全部展平进 `lib.character`（`lib.character[j] = lib.characterPack[i][j]`），
至此选将 UI 才能看到你的武将。

> ⚠️ **重点（第 2 次翻车实测验证过的坑）**：L11224 启动链里有个 `lib.config.characters` 白名单
> （config.js 的 `characters:[...]`，即「已启用武将包」列表）。
> 包在链中**先注册** `lib.characterPack` 和 translate（所以**包标签/包名能显示**），
> 但 `j=='character'` 这一支若**包名不在 `lib.config.characters` 里会被直接 continue 跳过**——
> **武将不进 `lib.character`、技能不进 `lib.skilllist`** → **选将界面出现「有标签、没武将」的空包**！
>
> **正解（雷霆万钧 L8959-8962 同款「包名注册三连」，扩展自己搞定）**：
>
> ```js
> lib.config.all.characters.push('tiandiguiyi');                          // ① 候选列表
> if (!lib.config.characters.contains('tiandiguiyi'))                     // ② 启用列表（白名单通过）
>     lib.config.characters.add('tiandiguiyi');
> lib.translate['tiandiguiyi_character_config'] = '天地归一';              // ③ 包名标签（UI 读这个 key）
> ```
>
> 三个缺一不可：①没有 → 包不出现；②没有 → 空包；③没有 → 标签显示 "undefined"。
> 另外 `game.js` 里有三处 `lib.characterPack → lib.character` 展平（L35486 在线分支 / L38094 回放），
> 保险起见可在导入后**手动幂等展平**（本仓库代码已这样做）。

#### 4.2.1 展平不是自动的（2026-09-10 源码复核）

**`game.import(type, content)` 对非 extension 类型只做一件事**：

```js
// game.js:37529-37534
const promise = Promise.resolve((...)(lib,game,ui,get,ai,_status)).then(content2 => {
    if (content2.name) {
        lib.imported[type][content2.name] = content2;
        delete content2.name;
    }
});
```

它**不碰** `lib.character` / `lib.skill` / `lib.translate`。真正写入 `lib.*` 的是启动期的
**一次性**循环（`game.js:15126-15181`）：

```
character[i].character      → lib.character[k]（并给 [4] 补空数组、收拢 skilllist）
character[i].skill          → lib.skill[k]
character[i].translate      → lib.translate[k]
character[i].characterIntro → lib.characterIntro[k]
```

而 `lib.imported.character` 在 `game.js:11541` 就被 `delete` 掉了，扩展加载循环
（`game.js:11550` 起）又在它**之后** —— 所以 `precontent` 里 import 的包
**不保证**被这趟循环扫到。踩坑表现就是「技能能发动、但武将名/包名是空的」。

**结论：扩展必须自己再展平一遍**（幂等，`== undefined` 守卫，两种时序结果一致）：

```js
if (pkg) {
    if (pkg.skill) for (var sk in pkg.skill)
        if (lib.skill[sk] == undefined) lib.skill[sk] = pkg.skill[sk];
    if (pkg.translate) for (var tk in pkg.translate)          // ★ 武将名能不能显示就靠这条
        if (lib.translate[tk] == undefined) lib.translate[tk] = pkg.translate[tk];
    if (pkg.characterIntro) for (var ik in pkg.characterIntro)
        if (lib.characterIntro[ik] == undefined) lib.characterIntro[ik] = pkg.characterIntro[ik];
    if (pkg.character) for (var cid in pkg.character) {
        if (!lib.character[cid]) lib.character[cid] = pkg.character[cid];
        if (!lib.character[cid][4]) lib.character[cid][4] = [];   // 15146-15148 同款
        var skl = lib.character[cid][3];
        for (var si = 0; si < skl.length; si++)
            if (!lib.skilllist.contains(skl[si])) lib.skilllist.add(skl[si]);
    }
}
```

**武将名为什么不显示，链路一次说清**：`game.js:22838` 无条件执行
`this.node.name.innerHTML = get.slimName(character)`；`get.slimName`（`game.js:61648-61651`）
第一件事就是 `var str2 = lib.translate[str]`，`if(!str2) return ''` —— **取不到译名就返回空串**，
名字位因此空白（不是报错、不是样式问题）。

**附带一条必须知道的引擎怪癖**（`game.js:15160-15162`）：

```js
if (j == 'translate' && k == i) {                          // k = translate 的键，i = 包名
    lib[j][k + '_character_config'] = character[i][j][k];  // ← 键 == 包名 → 改道！
}
else { /* ...正常写入 lib[j][k]... */ }
```

即当 `translate` 的键**恰好等于包名**时，引擎**不会**写 `lib.translate[包名]`，
而是改写成 `lib.translate[包名 + '_character_config']`。选将界面的包名标签读的正是后者，
所以「包名标签显示 undefined」要补的是 `_character_config` 这一条，而不是包名本身。

### 4.3 技能必须出现在玩家的技能列表里，才会被触发（最关键的坑！）

事件触发链（game.js）：

```
game.trigger(event)                       L32310
  → 从 lib.hook 桶取技能（addSkillTrigger L27805 注册：playerid_player_事件 → [技能名]）
  → arrangeTrigger 过滤（L15276 filter1）
    → filterTrigger（L33031）
      → player.getSkills(false).contains(skill)   ← L33042~33044！
```

**L33044 的 `!fullskills.contains(skill)` 判定**：触发前检查该技能名必须在
`player.getSkills(false)`（= `player.skills` + `invisibleSkills` + 装备技能）里，
否则**直接跳过**。

这解释了第 2 次翻车「选了角色但技能全不发动」的潜在机制，也解释了本心得的一个**重要设计决策**：

> **即使是隐藏子技能，也必须列进武将的技能数组**（`character:[..., ['mgj_dingce', 'mgj_nohurt', ...]]`），
> 开局 `addSkill` 逐个挂到玩家身上后才会被事件系统认领（`lib.character[3]` 循环 addSkill，见 L23092）。

隐藏方式：子技能对象加 `sub: true` + `popup: false` + `charlotte: true`（或用 `silent: true` 自动补全），
选将界面技能栏（`getStockSkills` L24007）会过滤掉 `sub`/`charlotte` 技能，不显示但功能正常。

### 4.4 trigger 写法与双键

```js
trigger: { player: 'phaseBegin' }            // 标准单键
trigger: { global: 'damageBegin' }           // 所有玩家监听
trigger: { global: 'gameStart', player: 'enterGame' }   // ★ 官方双键（L34301 同款）
trigger: { player: ['damageEnd', 'recover'] }  // 事件数组
```

解析逻辑（L33054）：`for (var i in info.trigger) if ((i == 'global' || player == event[i]) && has(...))`——
键为 `global` 时对所有玩家匹配；其他键按 `event[键] == player` 匹配。**双键/数组完全合法**。

定策用了 `{ global: 'gameStart', player: 'enterGame' }`：开局靠 `gameStart`（每个玩家 filter 一次），
复活/换将靠 `enterGame` 兜底，重复触发用自加标记 `mgj_ce_bound` 防重。

### 4.5 subSkill 的自动注册（以及为什么我弃用了它）

`game.finishSkill`（L44094）里有：`if (info.subSkill) Object.keys(...).forEach` 把
`子技能名 = 父名_子名` 注册进 `lib.skill`（L44153），并处理子技能翻译/优先级。

**但这只在 `finishCards()`（L44283，游戏启动遍历全部技能）时跑**。扩展包如果是
开局之后才导入，主技能**可能没被 finishSkill 处理过** → 子技能没被注册 →
`addSkill` 时 `lib.skill[子技能名]` 不存在 → 直接 return（L28177-28178 静默失败）。

**所以最稳方案**：不依赖 subSkill 自动注册，把子技能直接写成**顶层技能**（名字独立），
每个加 `sub: true` 隐藏显示。反正技能都列进角色数组，触发机制完全一致。
（`subSkill` 嵌套本身在官方角色里很多，若你导入时机在游戏启动链之前，也完全可用；
选择权在你。）

### 4.6 额外执行一个出牌阶段（不摸牌）的正确姿势

> ⚠️ **勘误（2026-09-10 源码复核，同日二次修正）**：本条原写
> `trigger.getParent().next.unshift(next)`，说「插到当前流程最前面」。
>
> **第一次复核**（只读了 sb.js / jsrg.js 两处）我断言「17 处全部是
> `trigger.next.push`，没有一处用 `getParent()`」—— **这个断言是错的，是抽样代替普查。**
> 后来用 [`atlas/tools/idiom.mjs`](atlas/tools/idiom.mjs) 做全库聚类才拿到真实分布：
>
> | 写法 | 处数 |
> |---|---|
> | `event.next.remove` → `trigger.next.push` | **8** |
> | `event.next.remove` → `trigger.getParent()` → `next.push` / `next.unshift` | **7** |
> | 其他机制（`insertPhase` / 直接 `phaseUse`） | 2 |
>
> 全库命中 17 个技能，**8 : 7 —— 不存在压倒性写法**。
> 教训：**语料是证据不是判决，而且要普查、不要抽样。**

现有两个流派，判据在引擎主循环（`game.js` 41700 附近）：`event.next` 队列是在
**当前事件每一步之间**被消费的。`trigger` 是**触发事件自身**（`game.js:41675`
`trigger=event._trigger`；`{player:'phaseBegin'}` 的触发事件就是 `phaseLoop`），
所以挂到 `trigger.next` 会落在 `phaseLoop` 的 step 7（触发 phaseBegin）与
step 8（建立 `phaseList` 各阶段，`game.js:15965-15968`）**之间** —— 正是「紧接着回合开始」。
挂到 `trigger.getParent().next` 则是父事件的队列，要等 `phaseLoop` 整体跑完才轮到，
即排到**整个回合之后**。

```js
var next = player.phaseUse();     // ① 创建（此刻挂在当前事件 _status.event.next 末尾）
event.next.remove(next);          // ② 从末尾摘掉
trigger.next.push(next);          // ③ 挂到触发事件自身的 next → 步与步之间即执行
```

可交叉验证的先例：

| 位置 | 技能 | 卡面 |
|---|---|---|
| `sb.js:3951` | 琉璃 | — |
| `jsrg.js:317` | 离叛 | 额外出牌阶段 |
| `yijiang.js:7399` | 当先 | 「回合开始时，执行一个额外的出牌阶段」← **与铸策②逐字同义** |
| `mobile.js:11691` / `diy.js:6516` / `sp.js:3804` … | — | 同派共 8 处 |
| `clan.js:2176` / `refresh.js:5700` / `xianding.js:8284` … | — | `getParent()` 派共 7 处 |

- `trigger.next` 是**触发事件自身**的后续队列。`phaseBegin` 在 `phaseLoop` 的 `'step 7'`
  触发（`game.js:15953-15956`），而阶段序列要到 `'step 8'` 才创建
  （`game.js:15965-15968` `player[event.currentPhase]()`）→ 挂在这里的 `phaseUse`
  正好落在「回合开始之后、正常阶段之前」，即卡面要的「额外」出牌阶段。
- 反过来，`trigger.getParent()` 拿到的是 `phaseLoop`，它的 `next` 队列是**整个回合跑完后**
  才消费的 → 原写法会把出牌阶段排到结束阶段之后。
- `phaseUse` 本身不含摸牌（摸牌是 `phaseDraw` 的事），天然满足「不摸牌」。

顺带一个必须记住的时机结论：**`phaseBegin` = 回合开始，每回合只发一次**（不是每阶段一次）。
判据就在 `game.js:15950-15968`：注释「回合开始后⑨」的 `'step 7'` 触发 `phaseBegin`，
之后 `'step 8'` 才建立 `phaseList` 的各阶段。所以拿 `{global:'phaseBegin'}` 做「你的回合开始时」
是安全的，永久化也不会变成「每阶段触发一次」。

### 4.7 锁定技 + 需要选择的内容

`forced: true` 只是「不弹发动按钮直接进 content」，**content 里照样可以弹
`chooseTarget` / `chooseBool`**（官方大量锁定技都是 forced + 内部选择），写起来没负担。

### 4.8 体力变动

沥血用 `trigger: { player: ['damageEnd', 'recover', 'loseHpEnd'] }` 覆盖掉血/回血/失去体力
—— **`loseHp` 是独立事件**（`game.js:26455 createEvent('loseHp')`），不产生 `damage` 事件，
只挂 `damageEnd` 会漏掉「失去体力」，与卡面「体力值发生变动」不符。
伤害数值的修改则用 `{global:'damageBegin'}` + 比对 `event.source` + `event.card` 判断单目标
（`get.info(event.card).selectTarget == 1` 排除南蛮/万箭等 AOE）。**改数值要改 `trigger.num`
（`game.js:41674` 伤害值就是 `event.num`），`event.damage` 在引擎里出现 0 次、改了等于没改。**

## 五、成品技能实现要点（`extension.js`）

- `mgj_dingce`（定策）：`forced + {global:['gameStart','gameDrawAfter'], player:'enterGame'}`，
  content 内 `chooseTarget` 选「策」目标，`mgj_ce_bound` 防重复；
  子技能 `mgj_nohurt`（damageBegin 相互免伤，`trigger.cancel()`）、
  `mgj_ce_remove`（die 时 chooseBool 移除）。
  > 触发时机为什么放宽成三个：`enterGame` 只在 `addFellow` / `restorePlayer` 里由
  > `game.triggerEnter` 创建（`game.js:44881`），**正常开局不会触发**；
  > `gameStart` 由各模式自己派发（如 `mode/identity.js:355`），时机受模式影响不保证；
  > 因此补 `gameDrawAfter` 兜底，三者谁先到就用谁（`ceBound` 保证只落一次）。
- `mgj_ce_bound` 为什么用 `player.storage.mgj_ce_bound` 而不是裸标记：裸标记取不到
  `lib.skill[...].intro`，`markSkill` 会直接 return（`game.js:27412-27417`）——
  纯记账状态放 `storage` 更干净（`mgj_picked1/2/3` 则故意用裸标记，正好借这个特性隐藏）。
- `mgj_zhuce`（铸策）：`{player:'phaseBegin'}`。**每回合四选一**，不是四连发 ——
  content 里先按 `mgj_picked1/2/3` 组装「当前还能添加」的选项，
  再用 `chooseControl(labels)` 弹一次选择，然后只 addMark 选中的那一项；
  前三项各限一次，用尽后只剩④时免询问直接落实。
  效果标记 `mgj_eff1 / mgj_eff2 / mgj_eff3_perm / mgj_eff4_perm`。
  子技能（顶层）：`mgj_eff1`（phaseBegin 回复体力）、`mgj_extra_phase`（额外阶段）、
  `mgj_boost`（伤害+1）、`mgj_skip`（phaseDiscardBefore cancel）。
- ⚠️ **「限一次」的语义**：卡面写的「限一次」限制的是**添加**次数，不是**发动**次数。
  ①②③ 一旦添加就**永久存在**（原实现在发动后 `removeMark`，属于把「限一次」误读成
  「一次性」，会让效果用一次就没了、还会让沥血的 X 凭空掉 1）；只有 ④ 是真正的消耗品。
  判据：`ceX()` 的语义是「『策』中**已添加**的效果数量」，应当只增不减。
- `mgj_lixue`（沥血）：`forced + {player:['damageEnd','recover']}`，
  X = 四枚效果标记之和，`player.draw(X+1,'nodelay')`，双方都摸。

全部技能 + 6 个隐藏子技能共 9 项全部挂进 `mouguojia_soul` 的技能数组（见 4.3）。

## 六、踩坑速查表

| 现象 | 根因 | 正解 |
|---|---|---|
| 放 `character\` 目录直接崩溃 | 内置包目录有白名单扫描，不兼容自定义 | 用 `extension\` + config.js extensions 列表 |
| 包名 undefined | `lib.characterPack` 直塞绕过注册链 | `precontent` 内 `game.import('character')` + 返回标准包对象 |
| 技能描述/包名不显示 | 写成 `translation`（复数） | 用 `translate`（单数） |
| **选将界面有包名标签、但包内没武将（空包）** | 包名不在 `lib.config.characters`（启用列表），L11236 白名单跳过武将注册 | **包名注册三连**：`all.characters.push` + `characters.add` + `translate[包名_character_config]` |
| 技能不发动 | 技能不在玩家技能列表，`filterTrigger` L33044 跳过 | 所有技能（含隐藏子技能）列进武将数组 |
| `str` 引用 undefined | 技能外顶层函数污染/闭包错位 | 辅助函数放 `game.import('character')` 回调闭包内 |
| 额外出牌阶段到了回合末才执行 | `phaseUse()` 默认插到事件流末尾 | `event.next.remove(next)` + **`trigger.next.push(next)`**（全库 8:7 两派，判据在引擎主循环而非票数，见 §4.6） |
| **武将名不显示（头像下有名字位、内容为空）** | `lib.translate[武将id]` 没注册。`game.js:22838` 无条件执行 `node.name.innerHTML = get.slimName(character)`，而 `slimName`（`game.js:61648-61651`）取不到译名时**直接返回空串** | 见 §4.2 附注：`game.import('character')` **不会**自动展平 translate，须在 `precontent` 里手动幂等展平 |
| 扩展里 import 的包时灵时不灵 | `game.import(type,content)` 对非 extension 类型**只写 `lib.imported[type][name]`**（`game.js:37529-37534`），展平是启动期**一次性**循环（`game.js:15126-15181`），而 `lib.imported.character` 早在 `game.js:11541` 就被 `delete`，扩展更在其后才加载 | 在 `precontent` 末尾**自己展平一遍** `skill / translate / characterIntro / character / skilllist`，全部用 `== undefined` 守卫保证幂等 |
| 包名标签显示 `undefined` | `game.js:15160-15162`：translate 的键**恰好等于包名**时会被改道写成 `<包名>_character_config`，`lib.translate[包名]` 永远为空 | 手写 `lib.translate['<包名>_character_config'] = '<中文名>'` |
| 标记在头像上不出现 | `markSkill` 在 `lib.skill[标记名].intro` 缺失时**直接 return**（`game.js:27412-27417`），不渲染任何标记；角标文字另取 `<标记名>_bg` 译名（`game.js:27584`） | 为每个标记名补一个纯显示空壳（含 `intro`），并补 `<标记名>_bg` 译名。纯记账用的标记（如 `mgj_picked1`）故意不给 intro 即可隐藏 |
| 启用扩展后仍然看不到 | 注册发生在开局 | 重启游戏 → 启用扩展 → **开一局新游戏** |
